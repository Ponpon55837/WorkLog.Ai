# 繁體中文工作報告寫作

先讀取正式的工作記錄與報告格式，再使用本指南改善文字。

第一段交代成果及適用範圍。每句以一個主要訊息為主，使用具體動詞；有前提時先寫前提，再寫操作或結果。用「建置完成後執行檢查」取代「後續進行相關驗證作業」。相關事實放在同一段，避免把文字拆成難以理解的短句。

同一概念使用同一名稱，例如「來源記錄」「來源涵蓋範圍」「目前期間統計」。保留程式碼中的 Session、Knowledge、MCP、API 等名稱；不要改寫命令、欄位名稱、引用原文或使用者提供的標題。數字、日期、版本、單位、狀態及來源 ID 必須與證據一致。

成果寫在摘要及重點；實際檢查與環境寫在驗證；來源缺口集中寫在一個涵蓋範圍段落。其他段落補充其影響，不重複貼上完整警語。區分「已通過」「失敗」「進行中」「未執行」及「資料不足」。沒有讀取完整來源時，不宣稱已完成完整整理。

修改前：「本次完成相關功能調整並完成相關功能驗證，來源限制於各節再次說明。」

修改後：「報告改為分頁讀取建立請求時保存的來源。回歸測試確認新增記錄後仍能讀到原來源。已作廢的來源維持不可讀取。」這些敘述仍須由實際來源支持。

本指南採用清楚、穩定且易翻譯的表達方式。ASD-STE100 是英文標準；本指南不稱為「中文 STE」，也不宣稱符合或通過該標準認證。句長只是閱讀提示，不能優先於事實完整性。
