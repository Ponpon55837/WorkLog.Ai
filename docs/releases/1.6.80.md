# Work Intelligence 1.6.80 更新說明

應用程式與 Agent plugin 版本為 1.6.80。資料庫維持 schema 39。升級後請重新連線 MCP，Agent 才會讀到新的結案說明。

## 開工記錄用同一個 key 再結案一次就完成

使用者要求開工時就顯示「進行中」時，Agent 原本要先以 `in_progress` 結案一次，收尾時再呼叫三個更新操作，分別更新摘要、工作摘要和中繼資料。

這一版改為：

- 開工時以 `verification.status: "in_progress"` 呼叫 `work_finalize_session`，就是開工記錄。`nextSteps` 可以不填，不會產生未結項。
- 收尾時用同一個 `idempotencyKey` 再呼叫一次，同一筆 Session 會原地改寫成完成的記錄。驗證狀態的變化會記進驗證歷程。
- 已完成的 Session 不會被較早送出的開工內容改回進行中：遲到的重試仍回 `idempotency_conflict`。

## 進行中記錄的回條不再顯示 completed

資料庫的 `execution_status` 永遠是 `completed`，進行中的記錄回條因此看起來像「已完成、驗證中」。現在驗證狀態是 `in_progress` 時，Agent 收到的回條不含 `executionStatus`，改附一行提示說明怎麼完成。REST、Web 和匯出格式不變。

## 開工時間的觀察

- 開工記錄不再清掉伺服器觀察到的開工時間和 HEAD。收尾時的 `startedAt` 與 Git 變更觀察沿用開工時的觀察點。
- 用 `work_update_session_metadata` 的 `completedAtNow` 完成 Session 時，也會結束該專案的觀察。下一段工作的開工時間不會再早於上一段的完成時間。
