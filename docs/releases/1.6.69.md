# Work Intelligence 1.6.69 更新說明

應用程式與 Agent plugin 版本為 1.6.69。這一版沒有資料庫 schema 變更，資料庫維持 35。專案匯出檔的結構與 1.6.64 相同，只是知識頁（`knowledge_pages`）的 `sections_json` 可能多一個內部的單段基準欄位；版本記錄不含這個欄位。

## 知識頁：單段更新

`work_save_knowledge_page` 現在可以只改幾個段落，不必為了改一段而重寫整頁。

- 不帶 `sections`，改帶 `upsertSections`（1–12 段，格式同 `sections`）和／或 `removeHeadings`（1–12 個標題），並且必須帶 `reviewToken`。與 `sections` 互斥，同時帶、或缺 `reviewToken` 都會回傳輸入錯誤。
- 比對方式：標題去空白後不分大小寫。已有同名段落就原地取代，否則附加在頁尾；頁面其餘段落維持已保存的內容。
- 上限在合併後才檢查：1–12 段、內容合計 8,000 字。
- 新的結果：`section_not_found`（`removeHeadings` 有頁面沒有的標題，附 `reason` 與 `headings`）與 `page_limit_exceeded`（附 `reason`、`sectionCount`、`maxSections`、`contentChars`、`maxContentChars`），兩者都不寫入。`reviewToken` 過期仍回傳 `version_conflict`。
- 冪等：同一個 `idempotencyKey` 重試回傳 `duplicate: true`；同一個 key 帶不同內容回傳 `idempotency_conflict`。
- 成功時，MCP 回傳精簡回條，不回整頁：`outcome`、`duplicate`、`page`（`slug`、`version`、`status`、`newSessionCount`，有才帶 `needsReview` 與 `updateRequestedAt`）、`sectionChanges: { replaced, added, removed }`，有遮蔽時另有 `redactions`。完整儲存與其他結果不變。
- 單段更新不推進 Session 涵蓋範圍，新的 Session 仍然是新的；不移動檢查游標；也不清除使用者的更新要求。要推進就用完整儲存，或 `work_mark_knowledge_page_checked`。
- 來源核對提示：取代或新增的段落不再顯示 `needsReview`，沒動到的段落保留原本的標記，所以單段更新不等於整頁已核對。

## 知識頁：聚焦讀取回傳 reviewToken

`work_get_knowledge_page_context` 帶 `query` 或 `headings` 的聚焦讀取，現在也回傳 `reviewToken`。這個 token 沿用頁面既有的涵蓋範圍，所以用它儲存不會把沒顯示的 Session 算成已涵蓋，讓 Agent 讀一兩段後就能直接做單段更新。

## Agent 指引

知識頁契約、`work_save_knowledge_page` 的說明與 work-intelligence skill 的知識指引，寫明單段更新的參數與結果、單段更新不推進涵蓋範圍也不清除更新要求，以及整頁改寫仍是完整維護與核對的做法。

## 已知限制

把 1.6.69 匯出的檔案匯入舊版 App 時，舊版會忽略單段基準，所以逐段更新過的頁面，在舊版中可能有些「來源需核對」標記消失。

## 升級

桌面 App 可在「設定」分頁的「更新」卡片檢查新版。依使用的安裝方式參考[更新 Work Intelligence](../user-guide.md#更新-work-intelligence)。這一版更動了 MCP 契約文字，MCP 相容性 ID 因此改變：升級後已連線的 Agent 會收到 `restartRequired`，請重新連線 Work Intelligence MCP；更新 Agent plugin 後也一樣。
