# Work Intelligence 1.6.53 更新說明

日期：2026-11-18。應用程式與 plugin 版本為 1.6.53。資料庫 schema 仍為 33，沒有 schema 變更，不需要 migration。

## 摘要

本版在桌面 App 加入**手動**的更新檢查：

- 只在使用者按下「檢查更新」時才連線到 GitHub 查詢最新版本。App 不會在啟動時、背景或閒置時查詢，也沒有設定開關；按下按鈕本身就是同意（ADR-40）。
- 有新版時顯示版本、發佈日期與更新說明（純文字），並提供下載 Windows 或 macOS 安裝檔的按鈕，以及開啟發行頁面的按鈕。
- App 內不下載、也不安裝更新（ADR-25）。安裝檔未經簽署，安裝時 Gatekeeper 或 SmartScreen 可能出現提示（ADR-38）；使用者自行安裝，資料會保留。
- 新增每日的相依套件稽核例外監看（`audit-exceptions-watch`），在 npm 出現修補版時通知維護者。

CI 結果待 PR 檢查完成後補上。Windows 11 與 macOS 的實機驗收尚未進行，仍為**待實機驗收**。

### 手動更新檢查

- **觸發方式**：桌面 App 修復視窗（設定頁）中的「更新」卡片按下「檢查更新」，或工作列的「檢查更新…」（開啟修復視窗並開始檢查）。沒有自動檢查，也沒有設定開關。
- **送出的請求**：只在主程序（main process）發出，`GET https://api.github.com/repos/<owner>/WorkLog.Ai/releases?per_page=20`。使用獨立的記憶體內 session（`update-check` partition），不帶 cookie 或任何憑證，不快取，拒絕所有重新導向。標頭只有 `Accept: application/vnd.github+json`、`X-GitHub-Api-Version: 2022-11-28` 與 `User-Agent: WorkIntelligence-UpdateCheck`。不送出版本、作業系統、機器識別碼或權杖。逾時 10 秒，回應上限 1 MiB；同時只進行一次檢查。
- **選擇版本**：略過草稿與預發布；tag 必須是 `vX.Y.Z`；取最高的版本與目前安裝的版本比較。
- **狀態**：
  - 已是最新版本；
  - 有新版本：顯示版本、發佈日期與更新說明；
  - 離線：無法連線到 GitHub；
  - 查詢次數受限：GitHub 回傳 403（沒有剩餘配額）或 429，顯示可再試的時間，不自動重試；
  - 錯誤：顯示簡短的錯誤代碼。

  每個狀態都提供「開啟發行頁面」。
- **更新說明**：只以純文字顯示，移除控制字元與雙向文字控制字元，上限 20 000 字元，超過時顯示「完整內容請見發行頁面」。不呈現 Markdown、圖片或 HTML。
- **下載按鈕**：主要按鈕為「下載 Windows 安裝檔」或「下載 macOS 安裝檔」，以預設瀏覽器開啟該平台的安裝檔：`Work-Intelligence-<x.y.z>-win-x64-setup.exe`、`-mac-arm64.dmg` 或 `-mac-x64.dmg`。按鈕旁有一行提示：下載後請用發行頁面上的 `SHA256SUMS.txt` 驗證檔案。其他平台與架構（例如 Windows arm64、Linux）只提供發行頁面。
- **連結檢查**：下載網址由 tag 重新組成，只有完全符合本儲存庫 github.com 發行頁面的網址才會開啟。畫面不顯示來自網路的任何網址；跨入主程序的只有固定的選項（安裝檔或發行頁面）。

### 不在 App 內安裝

更新維持 ADR-25 的手動下載路徑。App 不下載、不安裝、不在退出時安裝。因為 App 不自行安裝，本版不需要我們自己的 manifest 簽章（ADR-38）；使用者以 `SHA256SUMS.txt` 核對安裝檔。

### 測試

- 單元測試 62 項：`tests/desktop-core/update-check-{logic,request,controller}.test.ts`。
- 桌面 smoke 17 項：`apps/desktop/tests/desktop-smoke/update-check.spec.ts`，以本機的假 GitHub 伺服器驗證：啟動時與閒置時都沒有請求；按鈕流程；配額受限；逾時；格式錯誤的回應；HTML 以純文字顯示；安裝檔網址不合格時只提供發行頁面；請求標頭。
- 測試用的 API 來源與平台覆寫只存在於未封裝的測試建置，正式版的打包產物中沒有。

### 每日的相依套件稽核例外監看

- **工作流程**：`.github/workflows/audit-exceptions-watch.yml`，每天 UTC 03:37 執行，也可手動觸發。權限只有 `contents: read`，不需要任何 secret，也不是 PR 的必要檢查。
- **執行內容**：`node scripts/check-audit-ignores.mjs --registry`。當 npm 發布了受影響套件的修補版，或移除例外後 `pnpm audit --prod` 不再回報該 advisory 時，工作失敗，GitHub 會寄信通知擁有者，失敗訊息會列出移除步驟。
- 細節見[相依套件稽核例外](../security/audit-exceptions.md)。

## 升級

照常更新即可，不需要任何手動步驟。

## 未驗證與已知限制

- Windows 11 與 macOS 實機尚未驗證：更新檢查的各個狀態、安裝檔下載與 `SHA256SUMS.txt` 核對，以及 Gatekeeper 與 SmartScreen 提示的實際出現情形。
- 沒有 App 內的下載與安裝。Windows arm64 與 Linux 只提供發行頁面。
- 安裝檔未經簽署（macOS 為 ad-hoc 簽署，Windows 未簽署）。
- GitHub 的配額與回應格式由 GitHub 決定；測試以目前的回應格式進行。

## 待實機驗收

- Windows 11 與 macOS 實機上的：
  - 手動檢查的各個狀態，以及確認啟動時與閒置時沒有任何請求；
  - 安裝檔的下載、`SHA256SUMS.txt` 核對與安裝；
  - macOS 的 Gatekeeper 與 Windows 的 SmartScreen 提示，以及允許開啟的流程。
