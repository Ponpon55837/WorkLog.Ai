# Work Intelligence 1.6.68 更新說明

應用程式與 Agent plugin 版本為 1.6.68。這一版沒有資料庫 schema 變更，資料庫維持 35，專案匯出檔格式與 1.6.64 相同。

## 收尾回條：提示暫時狀態

- `work_finalize_session`、`work_update_session_work_summary`、`POST /api/work/finalize` 與 `PATCH /api/sessions/:id/work-summary` 的結果新增選填的 `nextStepsWarnings`：`{ items: [{ index, category }], message }`。只有已儲存的 `nextSteps` 項目看起來是本次工作內的暫時狀態時才會出現。
- `category` 有五種：`uncommitted`（尚未 commit）、`not_pushed`（尚未 push）、`pending_merge`（PR 等待合併，或尚未合回分支，也涵蓋「未合回」「未合入」「併入 main」這類寫法）、`ci_running`（CI 執行中）、`phase_not_started`（階段尚未開始）。
- 判斷只靠關鍵字，而且需要 Git、PR 或 CI 的上下文，可能誤判。這只是提示：伺服器不會刪除、改寫或拒絕任何項目。
- 冪等重播不會帶這個欄位；更新 work summary 時，只有請求帶了 `nextSteps` 才會檢查。回條只給項目位置與類別，不回顯項目文字。
- 比對規則只用有上限的視窗，每個項目一次合併掃描，耗時與文字長度成線性關係，測試裡也有惡意輸入的案例。

## Agent 指引

- 工作記錄契約與 work-intelligence skill 的第 4 步列出同樣的範例（尚未 commit、尚未 push、PR 等待合併或尚未合回、CI 執行中、階段尚未開始），並提到 `nextStepsWarnings`；工作記錄格式文件的 `nextSteps` 欄位也寫明這些項目不放進去。
- 修復與補登指引：commit、merge 或 push 在收尾之後才發生時，以 `work_update_session_metadata` 補上實際觀察到的 commit 與分支，不猜測。
- 知識頁契約與知識指引：branch、commit、PR 與合併狀態以 Git 為準，知識頁不記錄，需要時直接查 Git。知識指引也寫明，已在 Knowledge 的事實不複製進 Agent 自己的記憶檔，只留一個指標。

## 知識頁：「進行中的工作與未結項」的預設問題

- `in-progress` 頁的預設問題改為「目前有哪些尚未完成或尚未驗證的事項與已知限制？」，不再問進行中的工作，因為那是分支狀態，應該查 Git。頁面的 slug 與標題不變。
- 預設問題只在頁面第一次被要求時套用，已保存的頁面維持原本的問題。要改的話，請求更新時可以修改問題。

## 用量頁改版

- 專案、範圍與「掃描」固定在左欄（頁面夠寬時），只有結果區捲動。
- 摘要卡片附每日輸入 + 輸出走勢圖，旁邊是四張精簡卡片與 5 小時區段卡片。區段卡片顯示時間進度與起訖時間，不是額度。
- 沒有內層捲動區：結果欄較窄時，表格改為卡片。模型表格顯示輸入與輸出的比例條，以及占總量的比例。
- 修正文件捲動超出頁面主體的問題，原因是定位在畫面外的隱藏表頭。

## 其他

- 桌面 smoke 測試改為等到移除作業的 commit 記錄行出現，才走訪家目錄。移除作業會在寫完檔案後、記錄 commit 前刪除安裝的備份，太早走訪可能列出備份後卻無法讀取（v1.6.67 在 Windows 發行驗證遇到 ENOENT）。

## 升級

桌面 App 可在「設定」分頁的「更新」卡片檢查新版。依使用的安裝方式參考[更新 Work Intelligence](../user-guide.md#更新-work-intelligence)。這一版更動了 MCP 契約文字，MCP 相容性 ID 因此改變：升級後已連線的 Agent 會收到 `restartRequired`，請重新連線 Work Intelligence MCP；更新 Agent plugin 後也一樣。
