# Work Intelligence 1.5.2 更新說明

日期：2026-10-14。應用程式與 plugin 版本為 1.5.2；資料庫 schema 維持 30。

## 一個指令完成安裝

新增 `pnpm bootstrap`，作為唯一的安裝主線。它會先檢查 Node.js 與 pnpm 版本並列出計畫，確認一次後依序執行：安裝依賴、建置、連接 Agent（`pnpm setup:agents`）、詢問是否設定登入自動啟動，最後執行 `pnpm run doctor` 並印出下一步。

- 前兩步只寫入這個 repo。連接 Agent 與登入自動啟動會寫入全域設定，各自另外顯示預覽並要求確認，不確認就不會變更。
- 非互動終端只顯示計畫，加上 `--yes` 才會執行；`--skip-agents` 略過連接 Agent，`--service` 直接進入登入自動啟動設定。
- 可重複執行。`git pull` 後再跑一次就是更新；已安裝登入服務時不再詢問，改為提醒用 `pnpm service:install` 重啟服務。
- 已啟用 Work Intelligence plugin 的 Agent，`pnpm setup:agents` 會略過手動註冊並說明原因，避免出現兩份相同的工具與提醒。

README 的快速開始改為 `git clone` → `pnpm bootstrap` → `pnpm start`。plugin 與手動註冊列為「其他安裝方式」，與 bootstrap 二選一。

## 資料庫路徑

server、MCP、doctor 與登入服務現在用同一套規則解析 `WORK_INTELLIGENCE_DB`：

- 相對路徑一律以 repo 根目錄為基準，與從哪個目錄執行無關。
- 在 Windows 上，`C:Users...` 這類磁碟相對路徑（通常是 Git Bash 吃掉了反斜線）會直接拒絕並說明原因，不再默默在目前目錄建立空資料庫。macOS 與 Linux 不受影響。
- doctor 會把磁碟相對路徑回報為錯誤，並列出 repo 根目錄頂層的 `*.sqlite` 檔名（唯讀，不讀內容也不刪除）。

修正方式見[疑難排解](../troubleshooting.md#資料庫路徑錯誤windows-反斜線)。

## Node.js 版本

最低需求統一為 Node.js 22.13（`node:sqlite` 從這個版本起不需要旗標），根目錄 `package.json` 也宣告了 `engines.node`。

## 升級

```bash
pnpm db:backup
git pull --ff-only
pnpm bootstrap
```

若已安裝登入自動啟動服務，依提示執行 `pnpm service:install` 重啟服務，再重新連線 Agent MCP。本次不增加資料表或 migration，也不改寫既有資料。
