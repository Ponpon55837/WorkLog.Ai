# Work Intelligence 1.6.70 更新說明

應用程式與 Agent plugin 版本為 1.6.70。資料庫 schema 升到 36，升級時自動備份後遷移。專案匯出入包含新資料，仍可匯入 schema 31–35 的匯出檔。

## Agent 審查請求

使用者可以對「記錄中」的專案開一個 Agent 審查請求，入口在「知識」頁，也可以請 Agent 代為開啟。請求會把當下「待確認的 Agent 自主決策」與「已提出的 Knowledge 候選」做成快照，交給 Agent 審查。

- Agent 讀取快照後直接套用結論，每一筆都必須附理由。決策可以確認、駁回，或升為 Knowledge；候選可以接受（可附修改）或駁回。
- 沒有足夠證據的項目維持待確認，留給使用者。
- 快照建立後被改過、或已被審查的項目會略過，不會被覆寫。
- 同一個專案同時只有一個進行中的請求。
- 快照上限 500 筆，超出的筆數會顯示在畫面上。
- 處理超過 30 分鐘的請求會變成失敗，可以從失敗狀態繼續處理。使用者可以在 Web 取消請求。
- 完成後，結果會列出有新材料的知識頁。Agent 用既有的知識頁流程（單段更新）更新這些頁面；伺服器不會自行改寫頁面。

未結項的清理仍然需要人工核准，候選的提出方式也沒有改變。

## 審查紀錄與推翻

決策與候選現在記錄是誰審查的（使用者或 Agent）、理由、對應的請求與時間。舊版已審查的資料顯示為使用者審查。

在 Web 上，決策與候選清單可以篩選「由 Agent 處理」的項目並顯示理由。使用者可以推翻（overturn）Agent 的結論：該項目回到使用者的待處理佇列；若該結論建立了 Knowledge 且仍是使用中，這筆 Knowledge 會被封存，已經封存或刪除的則不變。被推翻的項目之後不會再被新的請求撿走。

## REST API

- `POST /api/agent-review-requests`、`GET /api/agent-review-requests`
- `POST /api/agent-review-requests/:requestId/cancel`
- `POST /api/session-decisions/:decisionId/overturn`
- `POST /api/knowledge/candidates/:candidateId/overturn`
- `GET /api/session-decisions?status=agent_reviewed`
- `GET /api/knowledge/candidates?reviewedBy=agent`

## MCP

新增三個操作：`work_request_agent_review`、`work_get_agent_review_context`、`work_submit_agent_review_verdicts`。work-intelligence skill 另有按需讀取的指引 `references/agent-review.md`。

## 資料庫與匯出入

schema 36 新增審查請求、請求項目與提交紀錄的資料表，並在決策與候選上記錄審查者、理由、請求與時間。專案匯出會包含這些資料，永久刪除專案或 Session 時一併清除。升級測試新增 schema 35 的樣本（取自 1.6.64）。

## 升級

桌面 App 可在「設定」分頁的「更新」卡片檢查新版。依使用的安裝方式參考[更新 Work Intelligence](../user-guide.md#更新-work-intelligence)。這一版新增了 MCP 操作，MCP 相容性 ID 因此改變：升級後已連線的 Agent 會收到 `restartRequired`，請重新連線 Work Intelligence MCP 才看得到新操作；更新 Agent plugin 後也一樣。
