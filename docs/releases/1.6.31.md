# Work Intelligence 1.6.31 更新說明

日期：2026-11-13。應用程式與 plugin 版本為 1.6.31；資料庫 schema 維持 33，不需要 migration。

## 摘要

這一版修正一個問題：`work_get_session` 的精準讀取（`view` 或 `select`）在部分用戶端讀不到 Session 本體。

## 精準讀取只回傳文字

MCP 工具的回應有兩個部分：文字 content 與 `structuredContent`。精準讀取自 1.5.0 起把選取的本體放在文字裡，`structuredContent` 只放識別與狀態欄位（`outcome`、`sessionId`、`projection`、`status`、`executionStatus`、`verification`、`changedFilesCount`），用意是不把同一份內容送兩次。

這個做法的前提是用戶端會把文字交給模型。在 Claude 桌面版的 Code 分頁，回應同時帶有兩者時，模型只收到 `structuredContent`，所以 Agent 看不到 summary、workSummary、decisions、files 與 links。同一個對話裡 21 次 `view: "handoff"` 與 `select` 讀取都沒有本體，只能全部改用完整讀取重讀。

1.6.18 起，伺服器指示、`work_get_session` 的契約與 work-intelligence skill 都把 `view: "handoff"` 設為預設讀法，所以在這類用戶端，原本用來省流量的讀法反而多花一次完整讀取。1.6.20 的更新說明曾寫「沒有證據顯示 Claude Code、Codex 或 Claude Desktop 擴充只讀其中一份」；現在至少有一個用戶端只讀 `structuredContent`。

現在精準讀取只回傳文字 content，不附 `structuredContent`：

- 每個用戶端都拿得到本體。
- 本體仍然只送一次，不會讓兩份都傳的用戶端收到兩次。
- 文字內容與先前完全相同。

不受影響、維持原樣的回應：

- 不帶 `view`／`select` 的完整讀取：`structuredContent` 是完整結果再加 `sessionId`、`executionStatus`、`changedFilesCount`、`verification`。
- `session_unchanged`：兩個部分都只有識別資訊。
- finalize 回條與四個 Session 更新操作的回條：`structuredContent` 是同一張回條再加三個欄位。

## 測試

- `tests/mcp/session-projection.test.ts` 原本要求精準讀取的 `structuredContent` 只含狀態欄位、不得有 `session`，所以測試全綠也看不出問題。現在改為要求：handoff 結果中用戶端可能交給模型的每一個部分（文字，以及有的話 `structuredContent`）都必須各自帶有本體；精準讀取沒有 `structuredContent`。
- `tests/mcp/result.test.ts` 對 `textResult` 檢查同一條規則。

## 未驗證

- 終端機版 Claude Code、Codex 與 Claude Desktop 擴充在兩個部分並存時交給模型哪一份，沒有測。這一版的修正不依賴它們的行為。
- 完整讀取在兩份都傳的用戶端會收到兩次內容，這是既有行為，本版沒有改。

## 升級

1. 取得 1.6.31 原始碼後執行 pnpm bootstrap（或 pnpm install --frozen-lockfile、pnpm build 與 pnpm check）。
2. 若已安裝登入自動啟動服務，執行 pnpm service:restart，確認輸出「服務已在執行 1.6.31」。
3. 透過 launcher 連線的 Agent 會自動切換到新版，不需要重新連線；只有 Agent 回報 `restartRequired` 時才重新連線一次。

自行讀取精準讀取結果 `structuredContent` 的 MCP 用戶端，請改讀文字 content。

完整流程見發行與升級指南（docs/release.md）。

從 1.6.14 或更早的版本升級時，請先讀 1.6.28 更新說明（docs/releases/1.6.28.md）的「從 1.6.14 或更早的版本升級」，再讀 1.6.29 與 1.6.30 的說明。
