# Work Intelligence 1.6.67 更新說明

應用程式與 Agent plugin 版本為 1.6.67。這一版沒有資料庫 schema 變更，資料庫維持 35，專案匯出檔格式與 1.6.64 相同。

## 用量頁：拿掉成本估算，改看輸入 + 輸出

- 1.6.66 的「估算成本佔比」用假設的價格倍率換算，而且不分模型，結果幾乎由快取讀取決定，容易誤導。這一版移除成本估算，用量頁、`pnpm usage:report` 與「複製給 Agent」都不再顯示。
- 主要數字改為「輸入 + 輸出」，也就是未快取的輸入加上輸出。快取讀取與快取寫入另外列出，不計入主要數字，並顯示快取讀取佔比（快取讀取 ÷ 全部輸入端 Token）。紀錄裡沒有每次請求是否命中，所以不叫命中率。
- 對話排行改依輸入 + 輸出排序。

## 依模型分列與目前 5 小時區段

- 新增依 Agent 與模型分列的 Token。Claude Code 取每則回覆記錄的模型，Codex 取每個回合宣告的模型。看起來不像模型名稱的值（例如路徑或 `<synthetic>`）一律顯示為「未標示模型」。
- 新增每個 Agent 目前的 5 小時區段，規則與 ccusage 的 `blocks` 相同：從第一筆用量所在的整點開始，長度 5 小時，中間停用滿 5 小時就開新區段。顯示輸入 + 輸出、已過時間、距區段結束與每分鐘輸入 + 輸出。只有查詢範圍包含現在時才會出現。

## Monorepo 子專案

- 在 monorepo 的根目錄開 Agent，但子專案（例如同一個 repo 底下的幾個前端專案）在 Work Intelligence 分別註冊時，根目錄的紀錄會被視為這些子專案的共用來源，用量頁把它們排成一組，並提供「選取整組」。
- 共用來源的每段對話只算一次，依序用以下依據分給子專案：
  1. 對話中 Work Intelligence 呼叫最常帶的 `projectRoot`。
  2. Claude 讀寫檔案工具所指檔案的資料夾。
  3. 對話紀錄的工作目錄（Codex 取 session_meta 與 turn_context）。
- 第 2、3 項需要超過一半、且至少 3 次命中同一組子專案才採用；其餘歸入該組的「共用（未分配）」。只選部分子專案時只計入分給它們的對話，選取整組才會計入未分配的部分。
- 每個專案依三種依據各分到幾段對話，會出現在用量頁、API、`--json` 與「複製給 Agent」，內容只有數字與專案名稱，不含路徑。

## 用量頁視覺

- 用量頁改版：數字以 K／M／B 顯示的摘要卡片、分成「計入」與「快取」兩列各自比例尺的 Token 組成、依日的輸入與輸出堆疊長條圖，以及附長條的排行表格。每張圖都有同樣數字的表格，亮色、暗色與窄螢幕都可閱讀。

## 其他

- 用量快取格式改變，更新後第一次掃描會重新讀取全部紀錄。
- 1.6.66 才加入的用量 API 欄位 `costShares`、`costMultipliers` 與 `estimatedCostUnits` 已移除，新增 `primary`、`cacheReadShare`、`models`、`daily`、`blocks`、`groups` 與 `allocation`。
- 打包後測試檢查殘留瀏覽器程序時，改以程序編號加建立時間確認父程序。Windows 重用程序編號時，先前可能把 `winlogon.exe`、`dwm.exe` 等系統程序誤認為瀏覽器的程序。

## 升級

桌面 App 可在「設定」分頁的「更新」卡片檢查新版。依使用的安裝方式參考[更新 Work Intelligence](../user-guide.md#更新-work-intelligence)。更新 Agent plugin 後，Agent 回報 `restartRequired` 時請重新連線 Work Intelligence MCP。
