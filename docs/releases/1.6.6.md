# Work Intelligence 1.6.6 更新說明

日期：2026-10-30。應用程式與 plugin 版本為 1.6.6；資料庫 schema 維持 30，不需 migration。

## 更新後一鍵重啟服務

- 新增 `pnpm service:restart`：不改寫服務設定，只停止舊的 server 再啟動，並等待 `/api/health` 回報這個 checkout 的版本。30 秒內沒有回應、或回報的版本不同時，會以錯誤結束並指出服務日誌位置。
- `pnpm bootstrap` 偵測到服務已安裝時，改為提醒執行 `pnpm service:restart`。

## 修正 Windows 更新後仍跑舊版

- 工作排程器的「結束」只會停止工作本身的 conhost，底下的 service runner、pnpm 與 server 會留下來繼續占用連接埠 3210。更新後新版因此無法啟動，舊版繼續服務，`/api/health` 仍回報舊版本。
- `pnpm service:restart`、`pnpm service:install` 與 `pnpm service:uninstall` 停止工作後，會另外結束這個 repo 的 `scripts/service-runner.mjs` 程序樹。只比對這個 repo 的 runner 路徑，不會動到手動執行的 `pnpm start`。

## 升級

1. 在舊版目錄執行 pnpm check 並記下資料庫位置；可先執行 pnpm db:backup。
2. 取得 1.6.6 原始碼後執行 pnpm bootstrap（或 pnpm install --frozen-lockfile、pnpm build 與 pnpm check）。
3. 若已安裝登入自動啟動服務，執行 pnpm service:restart，確認輸出「服務已在執行 1.6.6」。從 1.6.5 以前升級的 Windows 使用者若仍看到舊版本，代表舊 server 是由舊版程式啟動的；這次的 service:restart 會一併清除它。
4. 重新連線 Codex／Claude 的 MCP。
