# Work Intelligence 1.6.74 更新說明

應用程式與 Agent plugin 版本為 1.6.74。資料庫維持 schema 36，這一版不需要遷移。

## 保存回條提醒讀過但未回報的 Knowledge

Agent 在工作中讀過 Knowledge，保存時卻常忘了用 `appliedKnowledgeIds` 回報，Knowledge 的最後確認時間因此停在很久以前。現在 `work_finalize_session` 的回條可能另帶 `unreportedKnowledge`，列出這段工作讀過、這筆 Session 還沒回報的 Knowledge。

- 最多 3 筆，每筆只有 `id` 與標題（最多 80 字元），依最後一次讀取由新到舊；超過 3 筆時附 `total`。另有一句 `hint`，說明怎麼補報。
- 只算 `work_get_context`、`work_recall`、`work_search`、`work_search_knowledge` 回傳完整內容的讀取。`view: "compact"` 的清單不含內文，不算；Knowledge 歷史、知識頁與候選審核是維護讀取，也不算。
- 只算同一個專案、同一個 MCP 用戶端，而且在這段工作之內的讀取：從 Session 的開始時間到完成時間，同一用戶端在這段時間內於同專案保存過別的 Session 時，改從那次保存開始。
- 只列 active 的 Knowledge；本次或這筆 Session 之前回報過的，以及已列在 `knowledgeToReview` 的都不列。
- 補登（請求帶 `completedAt`）、沒有開始時間，或不知道 MCP 用戶端時不計算。全部回報過或沒讀過時，回條和以前一樣。

這份清單寧可少列也不誤列，但歸屬只看專案、用戶端與時間：同一個用戶端在同一專案同時進行兩段工作時，仍可能列到另一段讀過的 Knowledge。所以它只是提醒，不是用過的證據。伺服器不判斷 Knowledge 是否真的用上，也不會因此拒絕或延後保存。查詢在保存提交後執行，失敗只會省略這個欄位。

請求帶了 `appliedKnowledgeIds` 或 `contradictedKnowledgeIds` 時，回條另帶 `knowledgeFeedback: { applied, contradicted }`，是這次請求中這筆 Session 現在記錄的數量。

## 保存後補報 Knowledge

`work_update_session_metadata` 現在接受 `appliedKnowledgeIds` 與 `contradictedKnowledgeIds`，規則與 finalize 相同。

- 只回報這段工作真的用上且仍正確的 Knowledge；發現已不正確的放 `contradictedKnowledgeIds`；沒用上的不必回報，不要為了清掉提醒而回報。
- 這筆 Session 已用同一種方式回報過的 id 不再寫入，Knowledge audit 與回饋紀錄都不變，重送沒有副作用。
- 回應另帶 `knowledgeFeedback` 與 `knowledgeWarnings`（找不到的 id）；沒帶這兩個欄位時回應不變。
- REST 的 `PATCH /api/sessions/:id/metadata` 也接受這兩個欄位。`work_apply_metadata_backfill` 不接受：補登 metadata 不代表用過 Knowledge。

## 升級

桌面 App 可在「設定」分頁的「更新」卡片檢查新版。依使用的安裝方式參考[更新 Work Intelligence](../user-guide.md#更新-work-intelligence)。這一版改了 MCP contract 文字，MCP 相容性 ID 因此改變：升級後已連線的 Agent 會收到 `restartRequired`，請重新連線 Work Intelligence MCP；更新 Agent plugin 後也一樣。
