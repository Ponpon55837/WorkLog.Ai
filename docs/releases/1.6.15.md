# Work Intelligence 1.6.15 更新說明

日期：2026-11-12。應用程式與 plugin 版本為 1.6.15；資料庫 schema 維持 32，不需要 migration。

## Agent 讀取更精簡

這一版讓 Agent 用更少的 token 拿到更有用的內容，依實際資料（328 筆 Session）量測的結果調整：

- `work_get_context` 的 `omitted` 改為精簡指標：每區只有省略數量、讀取其餘內容的工具、最多 3 個 id，以及被省略且需要核對（`possiblyStale`／`needsReview`）項目的 id 與旗標。知識頁的受影響段落、來源 Session 標題與引用 id 不再在這裡重複，改由 `work_get_knowledge_page_context` 提供。帶 task 的 context 中，omitted 由約 5,800–6,800 字降到 1,700–2,100 字；省下的預算改留更多相關 Session、決策與知識頁段落，原本超過 10,000 字上限的 task context 也回到上限內。
- 沒有 task／paths 的 context 超出預算時，會先保留最新 3 筆 Session，等較舊的 Knowledge、決策與知識頁內容裁切後才省略它們；以前近期 Session 會最先全部被移除。
- 以 `projectRoot` 限定的呼叫只在頂層列一次專案：`work_get_context` 帶 `project`、`projects` 為空，近期 Session、Knowledge、未結項與 `relevant` 項目不再重複 `projectId`／`projectName`；`work_recall`、`work_list_sessions`、`work_list_outstanding_items` 改為頂層 `project: { id, name }`；限定專案的 `work_search_knowledge` 只帶 `project: { id, name, rootPath }`，不再附重複的 `projects`。實測 recall 平均由約 4,040 字降到 3,500 字，零命中的知識搜尋由 792 字降到 276 字，預設 Session 清單由 10,477 字降到 8,993 字。

不限定專案的呼叫維持逐筆專案欄位。REST 只有 `GET /api/context` 跟著 MCP 的 context 形狀改變；Web 使用的其他 REST 回應不變。

## 知識頁 not_found 診斷

`work_get_knowledge_page_context` 找不到頁面時，以前只回一句「先用 work_request_knowledge_page_update 要求頁面」，照做反而會為錯字建立新頁。現在回傳：

- `reasonCode`：`page_id_as_slug`（傳入的是本專案某頁的 id）、`slug_looks_like_id`（像 id 但不是本專案的頁面）、`slug_near_match`（與現有或預設 slug 只差兩個字元以內）、`page_not_requested`（從未要求過的預設頁）或 `page_unknown`。
- `existingSlugs`：這個專案現有的 slug（最多 20 個，其餘以 `existingSlugsOmittedCount` 計數）。
- `suggestedSlug`：可直接重試的 slug。

其他專案的頁面不會被比對或透露。原因代碼同時記入讀取稽核的 `errorCode`（`outcome` 維持 `not_found`），系統狀態頁的統計會把它列在錯誤代碼分布，但不算失敗數，之後可依資料看 not_found 的原因分布。

## 未納入

- `work_get_session` 完整讀取中的 `project` 物件維持不變：文件保證不帶 view／select 時回應與舊版相同，精簡它只省約 3%。
- `work_get_knowledge_page_context` 各段 `sourceSessionIds` 未改成索引：引用的 Session 大多不在回傳的 `sessions` 清單內，儲存頁面時也必須傳完整 id，改用索引會讓 Agent 對照出錯。

## 升級

1. 取得 1.6.15 原始碼後執行 pnpm bootstrap（或 pnpm install --frozen-lockfile、pnpm build 與 pnpm check）。
2. 若已安裝登入自動啟動服務，執行 pnpm service:restart，確認輸出「服務已在執行 1.6.15」。
3. 透過 launcher 連線的 Agent 會自動切換到新版並收到工具清單更新通知，不需要重新連線；只有 Agent 回報 `restartRequired` 時才重新連線一次。

完整流程見發行與升級指南（docs/release.md）。
