# Work Intelligence 1.6.55 更新說明

日期：2026-11-18。應用程式與 plugin 版本為 1.6.55。資料庫 schema 仍為 33，沒有 schema 變更，不需要 migration。

## 摘要

本版把桌面 App 改為單一視窗、分頁式介面，並讓桌面畫面與 Web 版使用同一套設計 token。本版改善下列項目：

- 單一視窗與分頁：Status、Agent、Settings、Data、Diagnostics。首次設定尚未完成時，另有 Setup 分頁（放在最前面，只在需要設定時出現）。切換設定頁不再需要工作列選單。
- 工作列選單縮短。工作列項目、啟動旗標與 Web 的開啟請求都只會聚焦同一個視窗並選取對應分頁，不會開第二個視窗。最後選取的分頁只在本次 App 執行期間記住。
- 應用程式選單列精簡。Windows 與 Linux 沒有應用程式選單；macOS 只保留 App、Edit 與 Window 選單。沒有 View、重新載入或 DevTools，打包版關閉 DevTools。
- 設計 token 移到共用套件 `packages/ui-tokens`，內容由 `apps/web/src/styles/tokens.css` 原樣移入；Web 版建置輸出除 import 路徑外完全相同。視窗即時跟隨系統的淺色與深色模式，測試禁止桌面 renderer 使用原始色碼。
- 無障礙：WAI-ARIA tablist、tab 與 tabpanel；方向鍵、Home 與 End；roving tabindex；可見的焦點框。操作進行中，分頁上會顯示忙碌徽章。診斷預覽、待確認的操作與進行中的操作在切換分頁後保留。4 秒輪詢只更新有變化的部分，且不搶走焦點。
- 首次設定完成後，Status 分頁顯示一次性的「開始使用 Work Intelligence」卡片，按鈕可前往設定 Agent。
- 視窗預設 920x760，最小 720x560，會夾在工作區內。上次的大小與位置只在本次 App 執行期間保留。

修復流程（NEEDS_REPAIR、首次執行、舊服務保留）不變。阻擋式卡片仍顯示在 Status 分頁，後端停止時也能運作。CSP、IPC allowlist 與 OperationCoordinator 的 BUSY 規則不變。新增的 `app:get-tab` 與 `app:remember-tab` 會檢查傳送者並嚴格驗證輸入，沒有新的特權 IPC。

Windows 11 與 macOS 的實機驗收尚未進行，仍為待實機驗收。

## 驗證（CI）

- Desktop smoke 在 Windows、macOS 與 Linux 全部通過。Linux 為 89 項通過，其中 12 項為新的視窗殼層測試。macOS 的 Cmd+C/V/X/A/Z/W 快捷鍵測試只在 macOS 執行。
- 打包版 smoke 與打包版頁面截圖在 Desktop package 中。
- 淺色與深色模式下，每個分頁，以及 NEEDS_REPAIR 與 needsSetup 狀態的截圖，以 CI artifact 上傳。
- CI：PR #385 的 head commit 見 PR。

125% 與 150% DPI 的版面是依 CSS 與最小視窗尺寸設計，未在實機顯示器上量測。

## 量測

production renderer 由 1.6.54 到 1.6.55（raw / gzip，位元組）：

| 檔案 | 1.6.54 | 1.6.55 |
|---|---|---|
| repair.js | 97,104 / 25,999 | 106,756 / 30,414 |
| repair.css | 8,197 / 2,576 | 11,249 / 2,679 |
| index.html | 441 / 284 | 799 / 425 |
| tokens.css（新，與 Web 共用） | — | 3,488 / 1,240 |
| 合計 | 105,742 / 28,859 | 122,292 / 34,758 |

合計 gzip 增加 20.4%（28,859 → 34,758 B），raw 增加 15.7%（105,742 → 122,292 B）。增加來自功能本身：六個分頁、原生對話框、差異式重繪、主題處理與共用 token。

視窗開啟時間（缺少資料庫時的修復視窗，三次取中位數，CI runner，門檻未變更；基準為 1.6.54 同一方法的同時段重跑。數字未驗證，以 CI 取樣為準）：

| 平台 | 1.6.54 基準 | 1.6.55 | 變化 |
|---|---|---|---|
| Linux | 610 ms | 531 ms | −13% |
| Windows | 1543 ms | 1669 ms | +8% |
| macOS | 1286 ms（先前取樣 1034–1127） | 1388 ms（p95 1752） | +8% |

此指標現在結束於 DB_MISSING 狀態在分頁視窗中可見的時間點。主程序內的計時標記顯示，新的選單、視窗範圍與分頁程式碼合計約 2 ms；預設視窗寬度由 780 改為 920 不影響結果（920 對 780 的中位數差距小於同一組內的離散）。

冷啟動（至後端 MANAGED 且健康證明通過，不含視窗）：macOS 1.6.55 為 1064 ms，同時段的 1.6.54 基準為 1271 ms（先前取樣 804–1010）。macOS runner 的取樣本身落在約 0.8–1.6 s，差距屬 runner 變異，不是程式碼變更造成。Windows 1620 ms，Linux 477 ms。

閒置時主程序記憶體：Linux 約 180 → 約 173 MiB，Windows 約 96 → 約 95 MiB，macOS 約 163 MiB（基準 163）。

效能門檻沒有變更。

## 已知限制

- 首次設定完成前，Agent 分頁可以選取。它處理的是 Agent 設定檔，不是資料庫。
- 最大化的視窗重新開啟時會還原為非最大化。
- 原生對話框（sheet）取得焦點時，Cmd+W 不會作用。

## 未驗證

- Windows 11 與 macOS 實機尚未驗收。
- 125% 與 150% DPI 的版面未在實機顯示器上量測。
