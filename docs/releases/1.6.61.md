# Work Intelligence 1.6.61 更新說明

日期：2026-11-19。應用程式與 plugin 版本為 1.6.61。資料庫 schema 仍為 33，沒有 schema 變更，不需要 migration。

## 摘要

本版讓桌面 App 能接手早期照文件手寫的 `pnpm start:mcp` 註冊。macOS 1.6.60 實機上，按「設定 Agent」只得到「有衝突，沒有寫入任何檔案」。

## 修復項目

- **手寫的 pnpm 註冊不再只是衝突。** 「改由桌面 App 管理」原本只認得 `node <checkout>/apps/mcp/dist/launcher.js`。現在也認得 `pnpm`、`pnpm.cmd`、`pnpm.exe`（絕對路徑或在 PATH 裡，也包含前面的 `cmd /c`）搭配 `--dir`、`-C`、`--dir=` 或 `cwd`，可含 `run start:mcp`。Codex `config.toml` 與 Claude MCP 註冊都只把 `command` 與 `args` 改寫成 launcher shim；`enabled`、其他 `env`、其他 MCP 伺服器、`[hooks.state]` 與指向其他資料夾的 `cwd` 都保留。只指向 checkout 的 `cwd` 會一併移除，否則 checkout 搬走後 launcher 會無法啟動。復原後兩個檔案與接手前逐位元組相同。
- **不會悄悄換到另一個資料庫。** `WORK_INTELLIGENCE_DB` 沿用既有的同一檔案比對：和 App 的不是同一個檔案時，不接手，Agent 卡片會說明，並提供原本就有的選擇。
- **遇到衝突會說明怎麼做。** 一般的「預覽變更」因為 Agent 有可接手的手寫註冊而被拒絕時，會提示改按「改由桌面 App 管理…」。不可接手的註冊，卡片用白話說明原因與可以怎麼處理，不要求輸入任何指令。
- **舊的 checkout hook 與 App 的 hook 並存（Codex 卡片一直顯示「設定衝突」）。** hook 的接手原本只認得和 setup 寫入一模一樣的 `node <script>`。現在也認得絕對路徑的 `node`／`node.exe`（可帶單純的選項、任何引號寫法），以及 `pnpm [--dir|-C <目錄>] [exec] node <script>`；會載入程式碼的選項（`--require`、`--eval` 等）不接手。同一個事件已經有 App 的 hook 時，舊 hook 視為重複，接手會把它移除（群組裡只有它時整個群組一起移除，同群組的其他或第三方 hook 保留），並可還原。不是我們的 hook 完全不動，也不會被判成衝突。checkout 自己的 `.codex/hooks.json` 不會被改動，若它也設定了提醒，卡片只顯示提示。
- **pnpm 指令中 script 名稱之後的 `--dir` 不算。** `pnpm start:mcp --dir <其他>` 實際跑的是原本的目錄，不再把後面的 `--dir` 當成 checkout。
- **plugin 自帶的 hook 與 App 的 hook。** 當 Agent 自己的 Work Intelligence plugin 帶有收尾提醒 hook（Codex：plugin 已啟用，或 `[hooks.state]` 有 `work-intelligence@…` 的信任狀態；Claude Code：plugin 已啟用），同時已安裝 App 或 checkout 的 hook，Agent 卡片會提示可能重複提醒。App 不會改動你的 plugin。

## 說明

- 接手後的項目保留原本的 `WORK_INTELLIGENCE_DB`（launcher 一律以明確的環境變數為準）。App 之後若更換資料庫，這個項目會留在舊檔案，直到重新設定；hook 則會跟著 App。
- 資料庫不同時顯示的路徑只出現在 Agent 卡片，不會進入診斷摘要。
