# Work Intelligence 1.6.19 更新說明

日期：2026-11-12。應用程式與 plugin 版本為 1.6.19；資料庫 schema 維持 32，不需要 migration。

## 報告整理的 context 不再每頁重複

Agent 整理一個月的報告時，要逐頁讀取 `work_get_report_context`。以實際資料量測，193 筆 Session 的月份需要 9 次呼叫、共 180,943 字；其中整期的報告區塊（totals、與上一期比較、projects、risks、decisions、trends、跨期工作）不隨來源頁變動，卻每一頁都重送一次，第 1–8 頁約 158,000 字裡有約 86,000 字是重複內容。區塊裡專案與風險的 `sourceSessionIds` 又把整期約 190 個 Session id 列了兩次，結果每一頁的預算都把 40 筆 evidence、8 條決策與 7 項風險整個移除，Agent 實際上拿不到這些資料。伺服器每頁只需約 30 ms；耗時來自 Agent 要讀寫的內容量。

1.6.19 的 agent 模式：

- 報告區塊只在 `sessionPage: 1` 回傳一次。之後的頁面 `report` 只含該頁 Session 的 `evidence` 與 `evidencePageInfo`，並帶 `reportBlockOnSessionPage: 1`，`projection.omittedFields` 列出 `report.block`。
- Agent 直接讀第 N 頁、重試某一頁，或重新啟動後接續整理時，再讀一次第 1 頁就會取得同一個報告區塊；伺服器不保存任何分頁狀態。整段期間只有一頁時，那一頁就是完整內容。
- 報告區塊內 `projects` 與 `risks` 的 `sourceSessionIds` 最多列 8 筆，其餘數量記在 `sourceSessionIdsOmittedCount`；完整來源仍在各來源頁。evidence 只以 `sessionId` 指向同一頁的 Session 預覽，不再重複標題與專案名稱。
- `view: "full"` 與 REST 回應不變。

## 知識頁 context 只帶改寫需要的部分

`work_get_knowledge_page_context` 原本每筆 Session 都附完整摘要與五段 workSummary，三個常駐知識頁各 20,752–23,705 字，其中 8 筆 Session 就佔約 12,900 字，另有每次相同的 `instructions` 文字。現在每筆 Session 只含 id、標題、完成時間，以及 workSummary 的 `outcomes`、`decisions`、`nextSteps` 各前 2 項、每項最多 100 字；截短處以 `…` 結尾，該 Session 帶 `truncated: true`。摘要、scope 與 verification 列在 `omittedSessionFields`，需要時以 `sessionReadWith`（`work_get_session`，`view: "handoff"`）讀取，做法與 1.6.18 的 Knowledge 候選 context 一致。Session 預算由 24,000 字改為 12,000 字。`instructions` 已移除：知識頁 contract 與 work-intelligence skill 已有相同規則。目前頁面的段落與段落引用的 Session id 不變，context 內每筆 Session 的 id 都可直接引用。

## Agent 指引

報告整理 contract、知識頁 contract、work-intelligence skill 與報告寫作 skill 都加上說明：報告區塊只在第 1 頁出現，翻頁時要保留；知識頁 context 的 Session 是預覽，依賴其中沒有的細節前要先完整讀取。報告的 `promptVersion` 維持 `report-synthesis-v4`：這個版本代表寫作規則，而寫作規則沒有改變，改變的只是 context 的傳送方式。

## 實測結果

同一份實際資料：

| 讀取 | 呼叫次數 | 修改前 | 修改後 |
| --- | ---: | ---: | ---: |
| 報告 context：193 筆 Session 的月份 | 9 | 180,943 字 | 156,378 字 |
| 報告 context：68 筆 Session 的月份 | 3 | 70,849 字 | 56,259 字 |
| 報告 context：5 筆 Session 的一週 | 1 | 13,385 字 | 12,561 字 |
| 知識頁 context：架構與慣例 | 1 | 23,705 字 | 14,935 字 |
| 知識頁 context：進行中的工作與未結項 | 1 | 20,752 字 | 11,982 字 |
| 知識頁 context：常見陷阱 | 1 | 22,670 字 | 13,900 字 |

報告省下的空間沒有全部變成較少的字數，而是讓原本被預算移除的內容送到 Agent：193 筆 Session 的月份第 1 頁保留全部 8 條決策與 7 項風險（修改前全部被移除），各頁合計送出 317 筆 evidence（修改前為 0）。5,000 筆合成 Session 的效能測試加入第 2 頁的 agent context，p90 約 39 ms，門檻 1,500 ms。

## 未納入

- 每頁 Session 數維持預設 24。改為 32 或 40 時，193 筆 Session 的月份可減為 7 或 5 次呼叫，但 68 筆 Session 月份的第 1 頁會因預算移除決策（32）或決策與風險（40）。需要更少呼叫時，Agent 仍可自行調整 `maxSessions` 與 `maxCharacters`。
- 頂層 `sourceSessionIds` 與 `sessions[].id` 相同，但它是既有欄位，這一版不移除。
- `work_get_report` 的 agent 預覽、REST 與 Web 都沒有改變。
- 架構與慣例頁本身（目前段落與引用）約 10,300 字，加上 8 筆 Session 預覽後為 14,935 字，略高於 14,000 字的目標；為了讓「進行中的工作與未結項」頁看得到未結項，Session 預覽保留 `nextSteps`。

## 升級

1. 取得 1.6.19 原始碼後執行 pnpm bootstrap（或 pnpm install --frozen-lockfile、pnpm build 與 pnpm check）。
2. 若已安裝登入自動啟動服務，執行 pnpm service:restart，確認輸出「服務已在執行 1.6.19」。
3. 透過 launcher 連線的 Agent 會自動切換到新版並收到工具清單更新通知，不需要重新連線；只有 Agent 回報 `restartRequired` 時才重新連線一次。

完整流程見發行與升級指南（docs/release.md）。
