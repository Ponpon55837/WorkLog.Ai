# Work Intelligence 1.6.3 更新說明

日期：2026-10-27。應用程式與 plugin 版本為 1.6.3；資料庫 schema 維持 30，不需 migration。

## 安全修正

- Zod 升級至 4.6.7，以修補 GHSA-mrhx-c7xc-m3w5；此公告沒有 Zod 3 修補版本。
- body-parser 2.x override 升至 2.4.0，以修補 GHSA-27r3-jxmh-p828。

## 檢索排序與評估

- 新增 pnpm bench:recall-scale，以 1,000、5,000 與 10,000 筆合成 Session 測試 recall/context 排序；只在本機執行，測試輸出限制於作業系統暫存目錄。
- 排序將只出現在 raw handoff 的查詢詞按半權重計算。私有評估的 recall MRR 從 0.927 升至 0.942，3 個答案排名上升、沒有答案下降；raw-only 答案仍會回傳。
- 搜尋結果現在會把延續系列中的最新 Session 放在前面：在前 100 個結果中，若較新的 Session 延續舊 Session 且分數至少達舊 Session 的 30%，就將新 Session 排在舊 Session 前面，兩筆都保留。私有評估的 hit@1 從 0.861 升至 0.884、hit@5 從 0.977 升至 1.000，context hit@5 從 0.875 升至 1.000。
- work_recall、work_search 與 work_get_context 的文件說明 high／low 只代表查詢文字的重疊程度，不代表結果能回答問題；排序計算沒有改變。

## Knowledge 查詢效能

- work_recall 與 work_get_context 改為批次讀取所有 Knowledge hit 的 stale/evidence 狀態。20 個 Knowledge hit、5,000 筆 Session 的本機 p90 從 1,414 ms 降至 113 ms；新增 250 ms 效能門檻。

## Windows 專案路徑相容性

- 開啟資料庫時會在既有 migration 前備份後，將舊專案根路徑改成 canonical 大小寫及分隔符格式，修復資料夾查詢時被誤判未追蹤的情況。若路徑屬於另一台電腦，或正規化後會與另一專案衝突，則不會改動該路徑。

## 升級

1. 在舊版目錄執行 pnpm check 並記下資料庫位置；可先執行 pnpm db:backup。
2. 取得 1.6.3 原始碼後，在新版目錄執行 pnpm install --frozen-lockfile、pnpm build 與 pnpm check。
3. 保留既有資料庫檔案與 WORK_INTELLIGENCE_DB，確認新版指向相同的資料庫絕對路徑。
4. 執行 pnpm start 並確認 Dashboard 與 /api/health 正常；重新連線 Codex／Claude，讓 MCP 載入新版。

完整流程與 schema 相容性限制見發行與升級指南（docs/release.md）。
