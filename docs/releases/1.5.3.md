# Work Intelligence 1.5.3 更新說明

日期：2026-10-14。應用程式與 plugin 版本為 1.5.3；資料庫 schema 維持 30。

## 用命令列開始記錄專案

新增 `pnpm track <資料夾> [--name <名稱>] [--yes]`，不必開 Web 也能把專案加入並設為「記錄中」。

- 相對路徑以執行命令時所在的目錄為基準。
- 寫入前會先顯示預覽：專案名稱、路徑、目前狀態 →「記錄中」，以及「記錄中」代表 Agent 可以讀取哪些內容。和其他專案的根目錄重疊時會警告。確認後才會寫入，預設為否。
- 非互動終端沒有加 `--yes` 時只顯示預覽；已經在記錄中的專案不會有任何變更。
- 只有你能在終端機執行這個命令，Agent（MCP）沒有對應的能力。已開啟的 Web 會自動更新；已連線的 Agent 下次讀取時就會生效，不需要重新連線 MCP。

## 診斷與維護

- 診斷命令改名為 `pnpm check`，舊的 `pnpm run doctor` 仍可使用。不要用 `pnpm doctor`，pnpm 11 把這個名稱保留給自己的命令。
- `pnpm db:maintain` 或 `pnpm db:redact --apply` 拿不到資料庫的獨占鎖時，會用唯讀方式說明原因：
  - server 是否正在執行，以及該怎麼停止。如果是登入自動啟動服務，會說明先 `pnpm service:uninstall`，維護後再用 `pnpm service:install` 恢復；Windows 也可以在工作排程器結束這個工作。
  - 目前有幾個 Agent MCP 連線（依此 checkout 計算）。
  - 兩者都沒有時，提示可能是其他程式開著這個資料庫檔。
- `pnpm start` 啟動時，如果偵測到已安裝的 Agent skill 或 Codex 保存提醒 hook 過期，會印出一行提醒。這項檢查只比對本機檔案，沒有問題或沒有安裝時不會輸出任何內容，也不會延遲或阻擋啟動。

## 其他

- 在 Windows 直接用 `node` 執行腳本時，不再出現 Node.js 的 DEP0190 警告。
- 發行實機驗收清單新增「Windows：pnpm bootstrap 互動安裝與更新」。
- MCP 測試的逾時時間和 storage、server 測試一致，避免 Windows coverage 偶發逾時。

## 升級

```bash
pnpm db:backup
git pull --ff-only
pnpm bootstrap
```

如果有安裝登入自動啟動服務，請依提示執行 `pnpm service:install` 重啟服務，再重新連線 Agent MCP。本次不新增資料表或 migration，也不會改寫既有資料。
