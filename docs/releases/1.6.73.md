# Work Intelligence 1.6.73 更新說明

應用程式與 Agent plugin 版本為 1.6.73。資料庫維持 schema 36，這一版不需要遷移。

## 未登錄路徑附上可能相符的專案

Agent 帶的 `projectRoot` 查不到已登錄專案時，以前回應只說「未登錄」。常見原因是資料夾搬家、換電腦、路徑打錯，或從專案的子資料夾呼叫。現在任何 MCP 操作因此略過時（`projectStatus: "unregistered"`），回應可能另帶 `matchingProjects`，讓 Agent 問使用者「是不是這個專案」。

- 每筆只有 `name`、`rootPath` 與 `status`，最多 5 筆。
- 只列「記錄中」（tracked）與「已暫停」（paused）的專案。「已忽略」（ignored）是使用者明確排除的專案，不提示；狀態仍為 `unregistered` 的列也不列。
- 相符條件只有三種明確關係，比對時忽略大小寫與結尾的分隔符：
  1. 路徑位於某個已登錄 root 之下（從子資料夾呼叫），排最前面，越近的 root 越前。
  2. 路徑的資料夾名稱與已登錄 root 的資料夾名稱或專案名稱相同（搬家、換電腦）。
  3. 已登錄 root 位於路徑之下（從上層資料夾呼叫），排最後，越淺越前。
  同一級再依專案名稱與 root 排序。不做相似字比對，所以 `atlas-v2` 不會對到 `atlas`。路徑本身是磁碟根目錄時只看第一種關係。
- 同時 `reason` 會補一句：請 Agent 詢問使用者是否就是其中一個，不要自己改用。

規則不變：未登錄、已暫停、已忽略的專案不讀取、不保存。這個提示只來自專案登錄表的名稱、路徑與狀態，回應不含任何專案資料；伺服器不會自動改用相符的專案，也不會替未登錄的路徑建立任何資料列。沒有相符的專案時，回應和以前完全相同。查找只在略過之後執行，讀一次登錄表、掃描一次。

## 知識搜尋的精簡清單

Knowledge 很多時，`work_search_knowledge` 的回應會很大：測試用 50 筆、每筆約 1,400 字內文的虛構資料，一頁回應是 87,220 字元。整理或去重只需要看清單，現在可以傳 `view: "compact"`：

- 篩選、排序、分頁（`pageInfo`）與 `match`、`relaxedMatches` 等欄位都不變。
- `items` 每筆只有 `id`、`kind`、`status`、`title`、`updatedAt`、`appliesToCount`（`appliesTo` 非空時）與 `needsReview`；不限定專案時另有 `projectId`、`projectName`。
- 不含內文、tags、references、`appliesTo` 與可信度訊號。回應另帶 `view: "compact"` 與 `readFull`，指向 `work_get_knowledge_history` 讀取單筆完整內容。

同一頁改用精簡清單是 10,872 字元。資料庫查詢只選這幾個欄位，`appliesTo` 的數量在 SQL 計算，不載入內文。不帶 `view`（或傳 `view: "full"`）時回應和以前完全相同；REST 的 `GET /api/knowledge` 不受影響。

## 升級

桌面 App 可在「設定」分頁的「更新」卡片檢查新版。依使用的安裝方式參考[更新 Work Intelligence](../user-guide.md#更新-work-intelligence)。這一版改了 MCP contract 文字，MCP 相容性 ID 因此改變：升級後已連線的 Agent 會收到 `restartRequired`，請重新連線 Work Intelligence MCP；更新 Agent plugin 後也一樣。
