# Work Intelligence 1.6.56 更新說明

日期：2026-11-18。應用程式與 plugin 版本為 1.6.56。資料庫 schema 仍為 33，沒有 schema 變更，不需要 migration。

## 摘要

本版修復 1.6.55 獨立審查（`docs/desktop/desktop-v1-review-1.6.55.md`）列出的高嚴重度問題，並把仍要使用者下指令的流程改為 App 內操作。本版改善下列項目：

- 當機復原接到產品。主程序啟動時會關閉上次中斷的操作，判斷依據是真實狀態（設定檔、資料庫身分與 schema、子程序、舊服務偵測），不採信 operation journal。結果以可關閉的橫幅顯示在 Status 分頁。
- App 內還原。「資料」分頁可從備份還原資料庫，只接受 App 產生的一次性備份權杖，拒絕較新 schema 與非 Work Intelligence 的檔案。
- Agent 可以在 App 內移除。「Agent」分頁新增「移除 Agent 設定」，使用與套用相同的預覽與交易流程。
- 舊服務流程不再要求執行指令。無法由 App 停用的舊服務，改為開啟工作排程器（Windows）或登入項目（macOS）。
- 文案修正。工作列與錯誤提示指向目前存在的分頁，已移除的文案已刪除，「忙碌」訊息會說明實際原因。

升級不需要任何手動步驟。設定、資料庫與備份都不會因為升級而改變。

Windows 11 與 macOS 的實機驗收尚未進行，仍為待實機驗收。

## 修復項目

### 高嚴重度

- **H-01 當機復原接到產品。** 主程序在讀取設定之後、首次設定與後端啟動之前執行 `recoverAtStartup`。中斷的操作只依真實狀態關閉：設定檔、資料庫身分與 schema、子程序、舊服務偵測。journal 為空時只多一次讀取。結果顯示為可關閉的橫幅。
- **H-02 App 內還原。** 「資料」分頁新增「從備份還原」。備份以不透明的一次性權杖選取，App 不接受任意路徑。還原經 OperationCoordinator 以 `restore` 種類執行，並拒絕較新 schema 與非 Work Intelligence 的檔案。開始前會提示先關閉 Agent。

### 中嚴重度

- **M-06 journal 損毀。** `operations-journal.json` 讀取失敗時，壞檔改名隔離，之後從空的 journal 重來。
- **M-11 Agent 移除。** 「Agent」分頁新增「移除 Agent 設定」，走 `uninstallPlan`，與安裝共用預覽與交易流程。
- **M-12 復原上次變更。** 檔案雜湊與套用後的值不符時（例如 `~/.claude.json` 被 Agent 改寫過），復原改為只撤銷 App 自己新增的條目，不再停在「需要手動修復」。
- **M-15 舊服務不再要求指令。** 舊服務無法由 App 停用時，不再顯示指令與「複製指令」按鈕。改為 `openSystemSettings` 開啟對應位置：Windows 開啟工作排程器（`%SystemRoot%\System32\taskschd.msc`），macOS 開啟登入項目，無法開啟時改開 LaunchAgents 資料夾。
- **M-16 文案指向錯誤入口。** 提示改為指向目前存在的 Status、Settings 與 Agent 分頁。

### 低嚴重度

- **L-08 忙碌原因。** 忙碌訊息會區分「另一個動作進行中」與「正在重新啟動服務」。
- **L-10 孤兒副本。** 本機副本的複製過程有 journal 紀錄，中斷後由復原清除。
- **L-20 手動修復訊息。** 結果為「需要手動修復」時，不再宣稱「已寫入的部分已還原」，並顯示需要處理的路徑。

### 防護測試

新增 `tests/desktop-core/no-command-copy.test.ts`，禁止桌面 App 的字串出現 pnpm、npm、終端機或指令的說法。之後若有人重新加入指令文案，測試會失敗。

## 升級與行為說明

- **啟動時可能出現復原橫幅。** 若上次執行中途被強制結束，下次啟動會顯示橫幅，說明復原做了什麼。橫幅可關閉，不影響後續操作。
- **還原前請先關閉 Agent。** 還原會取代現行資料庫，App 開始還原前會提示先關閉 Agent。
- **備份以一次性權杖選取。** App 不接受任意路徑，需要從「資料」分頁的清單選取備份。
- **舊服務的處理方式改變。** 無法自動停用時，App 會開啟系統位置，由使用者自行停用，不再給出指令。

## 已知限制

- **M-14 尚未修復。** 還原的最後一步在 Windows 上，若正式資料庫的 `-wal`、`-shm` 或檔案被防毒或索引器鎖住，rename 沒有重試，會直接失敗。排在 1.6.57。
- macOS 拖入垃圾桶後的「移除桌面整合」入口（DT-34）仍未做。
- 首次設定完成前，Agent 分頁仍可選取（沿用 1.6.55 的限制）。
