# Work Intelligence 1.6.22 更新說明

日期：2026-11-12。應用程式與 plugin 版本為 1.6.22；資料庫 schema 維持 32，不需要 migration。

## Agent 開始工作前要讀的內容少了三分之一以上

Agent 在第一次真正有用的呼叫之前，要先讀 server instructions、tools/list、work-intelligence skill、operation 索引，以及 `work_get_context` 與 `work_finalize_session` 的契約。舊版 skill 有 35,554 字，其中約三成是多數 Session 不會用到的流程：整理未結項、修正與回補、報告整理與寫作、知識頁、Knowledge 候選、部分讀取。同一條規則也常同時寫在 instructions、契約、skill 與記錄格式文件裡。

skill 現在分成每次工作都要讀的核心，加上六份按需讀取的流程指南：

- 核心保留隱私與追蹤規則（只處理 tracked 專案、預設拒絕、安靜略過、`<private>`、不記錄機密），dispatcher 與契約規則、開始工作的步驟、證據規則，以及分成十個步驟的 finalize 流程。
- `reading-records`：Session 部分讀取、context 的省略與補充指標、recall 排序與可信度、Knowledge 搜尋的寬鬆結果。
- `diagrams`：何時與如何附上 architecture v1 架構圖。
- `repair-and-backfill`：就地修正已保存的 Session、任務開始時建立的記錄、metadata 回補。
- `outstanding-cleanup`：以有證據的提案處理 Web 建立的整理未結項請求。
- `synthesis`：報告整理、各期間的分組粒度、`ReportSummary` 欄位對應與報告寫作。
- `knowledge`：Knowledge 候選、常駐知識頁與記錄 Knowledge。

每份指南都是 MCP resource `work-intelligence://agent/work-intelligence/references/<guide>.md`，也是 `SKILL.md` 旁邊的 `references/<guide>.md` 檔案。plugin、Claude Desktop 擴充與 standalone 套件都會帶上這些檔案，只載入 skill 資料夾、不讀 MCP resources 的 client 也讀得到。

重複的規則改放在 Agent 需要它的那一刻會讀到的地方：`work_get_context` 的細節留在它的契約；記錄欄位規則留在 finalize 契約與記錄格式文件；只在 finalize 時才適用的規則（未結項、`knowledgeToReview`、架構圖）改成只附在 `work_finalize_session` 的收尾契約。`docs/work-record-and-report-format.md` 保留 Session 記錄的定義，報告、回補與架構圖改指向對應指南。

## 沒有遺漏任何規則

拆分之前，先從 skill、記錄格式文件、server instructions 與受影響的契約抽出 350 條規範性敘述（must／never／only／不得等），拆分後以腳本逐條核對它仍出現在讀得到的地方：296 條逐字保留，54 條合併或改寫並逐條對應關鍵句。記錄格式文件中以中文寫的架構圖與 1.5.1 說明，改以英文寫進對應指南。核心新增一條規則：不得把機密、token 或個人資料寫進記錄、架構圖或 Knowledge。

`tests/mcp/agent-reading-budget.test.ts` 鎖定核心與固定閱讀量的上限，檢查核心本身寫出每條核心規則，也檢查各文字提到的指南與 resource URI 都存在且有提供；plugin 測試逐檔比對 plugin 內的指南與 `.agents` 版本。

## 其他 Session 更新也改成回條

`work_update_session_metadata`、`work_update_session_summary`、`work_update_session_title`、`work_update_session_work_summary` 的 MCP 回應比照 1.6.20 的 finalize 回條：`session` 只有 id、時間、驗證狀態與變更檔案數，另外只附伺服器改動或決定的事實——與請求不同的已存變更檔案清單、摘要、標題或 workSummary 段落（例如合併或遮蔽後）、遮蔽數量與 `timestampWarnings`。標題修正保留 `previousTitle`；`skipped`、`not_found` 與 idempotency conflict 原樣回傳。

實際資料上這些回應原本有 3,534–5,940 字；`tests/mcp/response-size.test.ts` 的合成資料上現在是 303–405 字，上限鎖定在 1,200 字。REST 與 storage 的結果不變。

## 未納入

- `pnpm setup:agents` 安裝到使用者目錄的 skill 仍只有 `SKILL.md`；這些 client 透過 MCP resources 讀取指南。
- 回條帶 `updatedAt` 但不帶 `revision`：`revision` 要讀完整 Session 才算得出來。
- schema 欄位說明（Zod `.describe()`）沒有改動。

## 升級

1. 取得 1.6.22 原始碼後執行 pnpm bootstrap（或 pnpm install --frozen-lockfile、pnpm build 與 pnpm check）。
2. 若已安裝登入自動啟動服務，執行 pnpm service:restart，確認輸出「服務已在執行 1.6.22」。
3. 透過 launcher 連線的 Agent 會自動切換到新版並收到工具清單更新通知，不需要重新連線；只有 Agent 回報 `restartRequired` 時才重新連線一次。用 `pnpm setup:agents` 安裝過 user-level skill 的使用者，再執行一次以更新複本。

完整流程見發行與升級指南（docs/release.md）。
