# Work Intelligence 1.6.41 更新說明

日期：2026-11-16。應用程式與 plugin 版本為 1.6.41；資料庫 schema 維持 33，沒有 schema 變更，也不需要 migration。

## 摘要

- **所有寫入都檢查 schema 版本**：先前只有 MCP 寫入會確認資料庫沒有被較新的程序升級；現在每個 SQLite 寫入交易（REST API、`track` 等長時間執行的 CLI 與 MCP）都在同一個寫入鎖內檢查。REST API 遇到這種情況回 503 `server_restart_required`，讀取不受影響；MCP 仍回 `MCP_RESTART_REQUIRED`。檢查結果以 `PRAGMA data_version`／`schema_version` 快取，只有其他連線提交後才重新查詢 `schema_migrations`。
- **Host 檢查加上 port**：loopback 名稱只在 server 實際 listen 的 port 上接受，另外接受每個允許 origin 的精確 host:port。預設的開發環境（Vite 5966）不受影響；若自訂 `WORK_INTELLIGENCE_WEB_PORT`，需要把該 origin 加入 `WORK_INTELLIGENCE_ALLOWED_ORIGINS`。
- **SQLite WAL-reset 修補檢查**：`/api/health` 與 `/api/system/status` 回傳 `sqlite: { version, walResetFixed, fixedIn? }`；`pnpm check` 列出 SQLite 版本，版本早於修補（3.51.3，回補版 3.50.7、3.44.6）時警告，系統狀態頁也會顯示警告。CI、發行 workflow 與 standalone smoke test 會列印並檢查 Node.js 內建的 SQLite 版本。
- **Windows 現代資料夾選擇視窗**：「選擇資料夾」改用與檔案總管相同樣式的 `IFileOpenDialog`，支援高 DPI 並顯示在瀏覽器前方；無法使用時自動改用舊式視窗。
- 新增專案、修改專案與定期清理摘要歷史改在寫入交易中執行，因此同樣受 schema 檢查保護。

## 不變的部分

沒有 schema 變更（33），沒有 migration。MCP 工具、匯出檔與既有資料都不受影響。支援的 Node 版本範圍不變（22.16 以上的 22.x，或 24 以上）。

## 升級

1. 取得 1.6.41 原始碼後執行 `pnpm install`，重新建置並重新啟動。已安裝登入自動啟動服務者可執行 `pnpm service:restart`。
2. 不需要 migration，也不需要重新匯入資料。Agent 不需要重新連線。
3. 執行 `pnpm check`，確認 SQLite 一行沒有警告。

## 未驗證與已知限制

- Windows 資料夾視窗只在 CI 以腳本內容與 exit code 單元測試驗證，尚需依[發行實機驗收清單](../release-checklist.md)的「Windows 11：現代資料夾選擇視窗」在實機確認。
- standalone 套件使用使用者自己的 Node.js；CI 檢查的是 CI 所用 Node.js 內建的 SQLite，使用者環境以 `pnpm check` 與系統狀態頁為準。
