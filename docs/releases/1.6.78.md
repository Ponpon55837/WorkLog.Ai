# Work Intelligence 1.6.78 更新說明

應用程式與 Agent plugin 版本為 1.6.78。資料庫維持 schema 38。升級後請重新連線 MCP，Agent 才會讀到新的說明與合約。

## Agent 結案前要讀的內容少了約三成

Agent 完成一次結案記錄前固定要讀的文字，從 42,244 字元降到 30,099 字元（−29%）。伺服器已經會檢查或會在回覆中說明的規則，不再重複寫在說明文件裡。

| 內容 | 1.6.77 | 1.6.78 |
|---|---:|---:|
| 伺服器 instructions | 1,934 | 1,801 |
| tools/list | 4,476 | 4,356 |
| 核心 skill | 13,918 | 8,871 |
| 操作索引 | 4,774 | 3,414 |
| work_get_context 合約 | 4,803 | 2,782 |
| work_finalize_session 合約 | 12,339 | 8,875 |

## 結案回覆會直接說下一步

- 未結項沒有被標記完成或取代時，回覆會逐項寫出原因，例如找不到、屬於其他專案、已處理、來源 Session 已作廢、正在整理待審。
- 文字裡有沒關閉的 `<private>` 標籤時，回覆會列出是哪些欄位。
- 需要複核的 Knowledge、需要修正的時間，回覆都會寫明該用哪個操作。
- 呼叫錯分派工具時，錯誤訊息會指出正確的那一個；欄位驗證錯誤會指出是哪個子欄位。

## 自相矛盾的結案請求會被拒絕

下列四種請求不會寫入任何資料，回覆會說明欄位、ID 與修正方式：

- 同一個未結項同時標記完成與取代。
- 標記取代，但沒有提供 nextSteps。
- 同一筆 Knowledge 同時回報為有用與有誤。
- 同時提供 startedAt 與 completedAt，而 startedAt 比較晚。

未知或其他專案的 ID 維持只警告、不拒絕。

## 知識頁儲存會檢查 reviewToken

Agent 儲存知識頁時帶回的 reviewToken，涵蓋點必須是這一頁實際讀得到的位置，否則不會寫入。沒有帶 reviewToken 的整頁儲存，不再把 Agent 沒讀過的 Session 算成已涵蓋。照原樣帶回 reviewToken 的用戶端不受影響；在 Web 手動編輯的涵蓋方式不變。

## 未追蹤的專案：先確認，再看資料夾

伺服器 instructions 寫明：在專案裡的第一個動作是 `work_get_context`，在它回覆之前不執行 git、不列目錄、不搜尋、不讀檔；專案不是追蹤中就停下來。

## 實測結果

用虛構專案、相同的 Agent 提示，在 1.6.77 與 1.6.78 各跑三次：

| 情境 | 1.6.77 | 1.6.78 |
|---|---|---|
| 一般結案 | 3/3 通過 | 3/3 通過 |
| 含機密與不該記錄的聯絡資訊 | 3/3 通過 | 3/3 通過 |
| 未結項與 Knowledge 回報 | 11 項通過 10 項 | 11 項通過 10 項 |
| 知識頁儲存遇到版本衝突 | 3/3 通過 | 3/3 通過 |
| 未追蹤專案（先確認再看資料夾） | 0/5 通過 | 5/5 通過 |
| 讀不到說明文件時結案 | 1/1 通過 | 3/3 通過 |

未結項情境中兩版都沒有自動附上架構圖，這一項不是這一版造成的，留待後續處理。
