# Work Intelligence 1.6.64 更新說明

應用程式與 Agent plugin 版本為 1.6.64。資料庫 schema 從 34 升到 35，首次啟動時會先自動備份，再執行 migration。

## Agent 讀取的回應大小

- Agent 讀取稽核新增 `responseChars`，記錄每次 MCP 讀取實際送出的回應字元數。算法是文字內容的長度，加上有 `structuredContent` 時序列化後的長度，單位是 JavaScript 字串長度（UTF-16 code unit），不是位元組也不是 token。只存數字，不存內容。
- 「系統狀態」頁的各工具統計新增回應大小的 p50、p95 與總和，每筆讀取也會顯示回應大小。升級前的紀錄沒有這個數字，不列入統計。
- `GET /api/agent-reads` 的每筆紀錄帶 `responseChars`，`GET /api/agent-reads/stats` 每個工具回傳 `responseChars: { count, p50, p95, total }`。

## 量測工具與基準

- 新增 `scripts/agent-usage-report.mjs`，讀取本機 Claude Code 的工作階段紀錄，只輸出加總：回合數、依名稱分組的工具呼叫數（Work Intelligence MCP 工具單獨列出）、各類 Token 與 MCP 結果字元數。不輸出訊息內容、檔案路徑或專案名稱。Codex 的本機紀錄屬實驗性支援，已用 Codex CLI 0.163 的實際紀錄核對，尚未與 Codex `/status` 比對。
- 新增 `docs/experiments/retrieval-baseline/`：虛構的合成專案、30 題檢索題、5 個 Policy 案例、5 個知識頁端到端情境、直接呼叫 storage 讀取函式的 runner，以及基準報告。
- 合成資料上的基準：檢索 30 題通過 28 題，Policy 案例全部通過。SQLite 讀取中位數 1.93 ms、p95 9 ms，知識頁 context 讀取 0.2 到 0.7 ms，SQLite 不是瓶頸。`work_get_context` 的回應約 9.8k 字元，約為 `work_recall` 的 4 倍。
- 知識頁端到端情境尚未用真實 Agent 執行。

## 資料庫

`agent_read_audit` 新增可為空的 `response_chars` 欄位。讀取稽核不在專案資料匯出內，匯出與匯入的欄位不變。1.6.64 產生的匯出檔標示 schema 35，要用 1.6.64 以上的版本匯入。

升級後，Agent 回報 `restartRequired` 時請重新連線 Work Intelligence MCP。1.6.64 之前的版本無法開啟升級後的資料庫（`DATABASE_SCHEMA_VERSION_TOO_NEW`）；需要退回時，請還原升級前的自動備份。

## 測試

- `pnpm test:scripts` 執行 `tests/scripts` 的測試，CI 在 Ubuntu、Windows 與 macOS 執行。
- 新增 schema 34 的升級樣本，由 1.6.63 build 產生。

## 升級

桌面 App 可在「設定」分頁的「更新」卡片檢查新版。依使用的安裝方式參考[更新 Work Intelligence](../user-guide.md#更新-work-intelligence)。
