# Work Intelligence 1.6.43 更新說明

日期：2026-11-16。應用程式與 plugin 版本為 1.6.43；資料庫 schema 維持 33，沒有 schema 變更，也不需要 migration。

## 摘要

- **桌面版階段 1（runtime spike）**：比較兩種 Agent runtime 的封裝方式：隨包官方 Node.js，與 Electron 以 Node 模式執行（`ELECTRON_RUN_AS_NODE`）。依 CI 量測與安全評估，採用**隨包官方 Node.js**（ADR-04）。理由：Electron 的 Node 模式需要保留 `RunAsNode` fuse，而 Electron 安全指引建議停用；Linux 上 Electron runtime 目錄約為 Node 的 2.2 倍，閒置 RSS 高約 32–34 MB；官方 Node.js 在 macOS 有 Developer ID 簽章，發行附 SHASUMS256 可供核對。代價是安裝包多出約 41–47 MB（壓縮後）的獨立 Node.js。
- **固定 launcher 與版本化 manifest（DT-23）**：Agent 的 command 將指向固定位置的 launcher（`<root>/bin/work-intelligence-launcher`，Windows 為 `.cmd`）。launcher 讀取 `current` 指向的 runtime，依 `runtime-manifest.json` 逐一核對每個檔案的大小與 SHA-256，拒絕未列出的檔案與指向 runtime 目錄之外的 symlink，只允許清單中的動作。shim 只讀取指標與啟動檔並執行 launcher；所有驗證都在 TypeScript 中完成，跨平台共用，並有單元測試。
- **無 Node 煙霧測試（DT-25）**：`pnpm spike:runtime:smoke` 在 PATH 上沒有 `node`、代理指向不可連線的 port 的環境中，依序驗證：Web UI、寫入合成資料庫、FTS5 搜尋、備份 worker、MCP stdio 的 `initialize` 與 `tools/list`、hook 動作，以及五種竄改情境（改一個位元組、manifest 損壞、多放檔案、遺失 `current`、不允許的動作）都被拒絕。CI 的 Linux 與 macOS 檢查全數通過（Linux 46/46、macOS 45/45）。
- **CI workflow**：`.github/workflows/desktop-runtime-spike.yml` 以 Windows、macOS、Ubuntu 乘上 Node、Electron 兩種 runtime 執行，只在 pull request（路徑篩選）與手動觸發時執行，並上傳量測 JSON。

- 官方 Node.js 24.22.3 內建 SQLite 3.54.1，FTS5 可用，並通過 WAL-reset 修補檢查。
- Linux 不在 V1 首發範圍，Linux 數字只作方向參考。
- 冷啟動上，Linux 的 Electron 中位數較快（伺服器快約 84 ms，MCP 快約 76 ms）；macOS 的 Node.js 伺服器中位數較快（252 ms 比 277 ms），MCP 幾乎相同。
- Linux 量測中閒置 CPU 皆為 0%；Windows 為 0–0.16%。
- Windows 數字來自 run 43859516900（1b09081）。兩個 Windows job 除了壓縮大小量測外全部通過：原本呼叫系統 `tar.exe`，而 Windows bsdtar 以 ANSI code page 讀參數，暫存路徑中的中文變成 `??`，無法開檔。量測已改為以內建 zlib 串流 gzip 自寫的 tar（`scripts/desktop-runtime-spike/compressed-size.mjs`），不再依賴平台工具；新方法在 Linux 量得 47.7 MB，比系統 `tar -czf` 的 46.6 MB 多約 2%（檔案順序與 gzip 實作不同）。
- Windows 上 Electron runtime 目錄約為 Node 的 3.7 倍，閒置 RSS 兩者相近。

## 不變的部分

沒有 schema 變更（33），沒有 migration。伺服器、CLI、MCP 與匯出的行為不變。沒有新增相依套件，lockfile 沒有變更。plugin 與 standalone 套件的 MCP 設定沒有改動，仍使用原本的啟動方式；本版尚未把 launcher 接到任何 plugin 或安裝程式。匯出欄位清單的單一來源（`PROJECT_DATA_EXPORT_COLUMNS`）已併入本版，匯出輸出的位元組不變。

## 升級

1. 本版沒有可安裝的桌面 App，也不會安裝任何 runtime。開發者可執行 `pnpm spike:runtime:build` 與 `pnpm spike:runtime:smoke` 重現量測。build 需要網路，用來下載官方 Node.js 或 Electron 的封存檔；smoke 不需要網路。
2. 不需要 migration，也不需要重新匯入資料。
3. 執行 `pnpm check`，確認 SQLite 一行沒有警告。

## 未驗證與已知限制

- **Windows 只有 CI 結果**：Windows CI 的功能檢查全部通過，壓縮大小待下次 PR CI。階段 1 的 gate 要求 Windows 11 與 macOS 實機驗收，尚未進行，gate 因此尚未通過。
- **Windows ACL 未檢查**：launcher 在 Windows 回報 `acl: "not-implemented"`，不會因此通過權限檢查。Windows ACL 檢查（程式中的 TODO，須於 Windows 安裝程式發行前完成）完成前，Windows runtime 不得用於發行。
- **Windows 的 stat 快取較弱**：NTFS 的變更時間可被使用者還原，因此在 Windows 上快取只防意外損壞，不防刻意竄改。
- **驗證與執行之間有時間差（TOCTOU）**：shim 先執行 runtime 的 Node.js 執行檔，之後才由 launcher 核對檔案。真正的邊界是目錄的擁有者與 ACL，以及之後的程式碼簽章。
- **SHASUMS256 與封存檔來自同一來源**：它只能發現損毀或被替換的檔案，不是獨立的信任根。發行前必須驗證發行簽章，這項尚未實作。
- **沒有 runtime 清理**：舊版 runtime 目錄不會被刪除（DT-24 尚未實作）。
- **沒有接到 Agent 設定**：plugin、standalone、MCPB 與手動設定尚未改為指向 launcher（R4 §3.2）。
- **檔案清單刻意嚴格**：`.DS_Store` 之類的多餘檔案會造成 `RUNTIME_FILE_UNEXPECTED`。
- **Windows 的 `%*` 與 `!`**：`.cmd` 的參數若含 `!`，在延遲展開下可能被改寫。
- **Node.js 發行簽章未驗證**：spike 預設鎖定 v24.22.3，只核對同一來源的 SHASUMS256，尚未驗證官方 GPG 簽章。
- **SQLite 版本以發行產物為準**：本次的 3.54.1 來自開發與 CI 的 Node.js。發行產物內的 SQLite 版本仍以 release 流程的列印為準。
- **Windows 實機驗證尚未完成**：所有 Windows 項目都是待實機驗收。
