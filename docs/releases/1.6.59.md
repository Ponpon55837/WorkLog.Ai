# Work Intelligence 1.6.59 更新說明

日期：2026-11-19。應用程式與 plugin 版本為 1.6.59。資料庫 schema 仍為 33，沒有 schema 變更，不需要 migration。

## 摘要

本版把 1.6.58 的守門清單列出的缺口接上，讓 App 提供的設定、訊息與通道都能從視窗使用。

- **換新電腦時還原。** 「從備份還原」會找出備份記錄的專案資料夾裡這台電腦上不存在的，用原生視窗問你它們現在在哪裡：選一個資料夾（App 會找出同名的專案資料夾並對應路徑，邏輯與命令列的 `--remap-root` 相同）、可重複選、略過或取消。頁面仍只送出一次性的備份 id，所有路徑都留在 main。Web 備份頁的桌面說明也已更新。
- **App 內整理資料庫。** 「資料」分頁可以整理資料庫（自動備份、完整性檢查、VACUUM、重建搜尋索引），也可以只讀地檢查完整性。整理是協調器的 `maintenance` 操作；有其他操作、Agent 連線、匯入或備份進行中時拒絕，開始前會先確認。「狀態」分頁與 Web「系統狀態」會顯示可回收的空間與最近一次整理的結果。
- **回到上次正常的連接埠。** 設定的連接埠被占用或不被允許時，服務會改用上次驗證過的連接埠啟動（仍須通過健康與身分檢查），並在「狀態」分頁說明；你的設定不會被改寫。資料庫不會被自動換成別的檔案，也不會回退 runtime；回退也失敗時，維持原本的錯誤進入修復流程，資料不會被更動。
- **備份位置。** 「設定」分頁可以更換備份位置：原生資料夾視窗、寫入測試、套用資料庫的儲存區風險規則（網路磁碟不可用；外接磁碟、雲端同步或硬連結資料夾要先問你）、重啟服務使用新資料夾，失敗時改回原資料夾。已經存在的備份不會被移動，卡片也這樣說明。
- **診斷摘要的安裝標籤。** 診斷預覽帶有簡短的安裝標籤（安裝 id 的前 8 個字元），回報問題時能對應到安裝，卻不洩漏完整 id。

## 修復項目

- **同時寫入設定。** 所有設定變更經過同一個序列佇列，先寫檔再更新記憶體，兩個重疊的變更不會互相覆蓋欄位。
- **Windows 啟動項目。** 系統已有符合的登入項目時，App 啟動不再重新登錄，所以在 Windows 啟動設定中被關掉的標記不會被清除。

## 測試與守門

- `lastKnownGood` 與 `installId` 不再是設定欄位守門的例外。
- 新增未使用 export 的守門（`pnpm check:unused-exports`，knip，基準檔只會變少）；只有測試用的 helper 以 `@internal test-only` 標註。
- 新增文件說法守門：使用者文件出現已被取代的說法（例如「目前沒有還原流程」「修復視窗」）時 CI 失敗；發行檢查清單要求每個使用者可見的功能在同一次變更更新 `docs/user-guide.md`。

## 未完成

- Windows 11 與 macOS 實機驗收。
- 資料庫與 runtime 不會自動回退（只回退連接埠）。
