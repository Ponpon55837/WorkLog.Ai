# Work Intelligence 1.6.9 更新說明

日期：2026-11-08。應用程式與 plugin 版本為 1.6.9；資料庫 schema 升為 32，第一次啟動會先自動備份再套用 migration。

## 資安

- **遮蔽規則不再拖慢整個服務**：保存工作記錄時會先遮蔽密碼、token 等敏感資料。原本遇到很長且沒有空白的文字、重複的 `token=`，或 `://` 後面接很長的字串時，遮蔽時間會隨長度平方成長，200,000 字約 46 秒，期間 API 與 MCP 的其他請求全部卡住。現在每條規則都是線性時間，同樣的輸入只要幾毫秒；遮蔽結果不變，另外修正一個情形：連線字串的密碼與使用者名稱相同時，舊版遮到使用者名稱、密碼仍外露，現在會遮住密碼。
- **`<private>` 區塊不會被保存**：用 `<private>` 與 `</private>` 包住的內容，在任何寫入前都會換成 `[REDACTED:private_block]`，回應只回報數量。區塊必須有結尾標籤；只寫了開頭的 `<private>` 會照原文保存，方便在記錄裡提到這個標籤。Handoff 檔會先移除區塊再截斷長度，跨越截斷點的區塊也會被移除。
- 知識頁更新請求的標題與問題現在也會遮蔽；`pnpm db:redact` 與匯出匯入在遮蔽 JSON 欄位時改為逐值處理，不會破壞 JSON。

## Agent 讀取更省

- **重讀未變動的 Session 不再重送全文**：`work_get_session` 回傳內容指紋 `session.revision`。Agent 重讀一筆完整內容仍在目前對話中的 Session 時帶上 `knownRevision`，內容沒變就只收到 `session_unchanged`。實際資料中約 38% 的 Session 讀取是同一個 Agent 在 60 分鐘內重讀同一筆。
- **一次呼叫確認追蹤狀態**：帶 `projectRoot` 的 `work_get_context` 直接回傳 `projectStatus` 與 `tracked`，Agent 開工與保存前各呼叫一次即可，不再另外呼叫 `work_get_project_status`（原本占 Agent 讀取 14%）。

## 長對話壓縮後不遺失工作狀態

- Claude Code 壓縮對話前，若記錄中專案有尚未保存的改動，會要求壓縮摘要保留「尚未保存、開始時間、改過的檔案」。
- Claude Code 與 Codex 壓縮後，會在 Agent 的上下文補上保存提醒與開始時間。
- 修正：壓縮摘要原本被當成使用者訊息，壓縮後這段工作的開始時間會被誤設成壓縮的時間。
- 保存的強制提醒仍由原本的 Stop hook 負責；壓縮相關 hook 不會阻擋壓縮。

## 讀取耗時與失敗原因

- Agent 讀取稽核新增每次讀取的耗時與失敗代碼（`invalid_input`、`database_busy`、`restart_required`、`internal_error`），不保存任何內容或錯誤訊息。
- 系統狀態的「Agent 讀取」顯示每筆耗時，以及各工具的次數、p50／p95 耗時與失敗數；REST 為 `GET /api/agent-reads/stats`。

## 升級

1. 取得 1.6.9 原始碼後執行 pnpm bootstrap（或 pnpm install --frozen-lockfile、pnpm build 與 pnpm check）。第一次啟動會先備份資料庫，再升級到 schema 32。
2. 若已安裝登入自動啟動服務，執行 pnpm service:restart，確認輸出「服務已在執行 1.6.9」。
3. 執行 pnpm setup:agents（或更新 plugin）以註冊新的壓縮前後 hook；Agent 重新連線一次即可看到新的 MCP 參數與指引。

完整流程見發行與升級指南（docs/release.md）。
