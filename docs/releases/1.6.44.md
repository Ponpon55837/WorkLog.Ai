# Work Intelligence 1.6.44 更新說明

日期：2026-11-16。應用程式與 plugin 版本為 1.6.44；資料庫 schema 維持 33，沒有 schema 變更，也不需要 migration。

## 摘要

- **桌面版階段 2（安全最小桌面）**：新增 Electron 殼（`apps/desktop`，Electron 45.3.2）。主程序在 `ready` 前取得單例鎖，第二次啟動立即結束。提供 tray（macOS 為選單列）與修復視窗。退出流程先確認，停止受管服務；若有進行中的操作則取消並有界等待，最後確認 port 釋放。登入時在背景執行預設關閉，開啟需使用者同意；背景啟動不顯示視窗。
- **後端子程序生命週期（DT-11）**：`packages/desktop-core/src/backend` 的 `BackendSupervisor` 只操作自己 spawn 的子程序。子程序以 `start --desktop-ipc` 啟動，環境變數採 allowlist 並固定 `PATH`。DB 路徑、port 與備份目錄經私有 IPC 傳遞，runId 只經 IPC 送出。`/api/health` 以 HMAC 證明身分，不回傳 runId。停止順序為 IPC `shutdown`、POSIX 的 `SIGTERM`、`kill`（Windows 為 `TerminateProcess`），最後確認 port 釋放。
- **修復視窗（DT-16）**：固定 `wi-repair://` scheme、sandbox、context isolation、最小 preload；每個 IPC 通道先驗 sender，再以 zod 驗輸入；拒絕導覽、`window.open`、webview 與權限請求；採嚴格 CSP。
- **無法取得資料資料夾時的處理**：平台無法提供 App 的資料資料夾時（Windows 上是缺少 Roaming AppData），App 先把原因寫到 stderr，立即顯示原生錯誤對話框並以代碼 1 結束，不等 `ready`；此時還沒取得單例鎖，也沒有建立 tray 或後端。不能等 `ready`，是因為缺少這個資料夾時，Electron 會在 `ready` 之前於原生層檢查 session 資料路徑而中止（Windows 上的結束代碼是 0xFFFF7003，即 Crashpad 的「未連上 handler」）。Windows 上若存放預設資料夾的上層資料夾不存在，也直接判定失敗，因為 Electron 可能照樣回傳預設路徑。這個判斷（`resolveUserDataDirectory`）有單元測試。開發用的資料夾重新導向會在第一次讀取預設路徑前套用。
- **整份資料庫下載加快約三分之一**：`POST /api/export`（`{}`）的暫存副本只串流一次就刪除，所以寫入時略過 SQLite 的 fsync（`exportTo(target, { durable: false })`），並以 1 MiB 為單位讀取。內容相同，送出前仍會檢查快照；備份與 CLI 匯出照舊寫入磁碟。專案資料匯出改用 `Buffer.from` 編碼 JSON，位元組相同。
- **桌面效能量測與閘門**：煙霧測試新增效能 spec（`apps/desktop/tests/desktop-smoke/performance.spec.ts`），三平台都跑，只用合成資料，每項量 3 次、取中位數：冷啟動（啟動到 MANAGED 且 health 證明通過）、DB 不存在時開出修復視窗（啟動到「選擇資料庫」按鈕可見）、退出（到後端程序消失且 port 釋放）、MANAGED 後 5 秒的閒置記憶體（主程序取自 `app.getAppMetrics()`，後端在 Linux 讀 `/proc`、macOS 用 `ps`、Windows 用 `Get-Process`）。中位數不得超過 `perf-gates.ts` 的各平台閘門，該檔案也寫明每個閘門的依據。CI 每次都會把結果上傳為 `desktop-perf-<os>.json`。
- **後端提早啟動**：App 取得單例鎖後就開始讀設定、檢查 port 並啟動後端，不再等 Electron 的 `ready` 與 tray，子程序因此與 Electron 的初始化同時進行。只有會顯示東西的步驟（視窗、Dashboard、通知、登入項）才等 `ready`；後端若提早結束，復原流程也等 `ready` 後才執行。啟動時若 active 紀錄（port、runtime 版本與資料庫身分）沒有變，不再以 fsync 重寫設定檔。主程序日誌只在第一次寫入時建立資料夾，不再每行都建立。
- **退出語意與備份時間（DT-35）**：退出確認訊息與 tray 文字都寫明「退出後不會每日備份」，並顯示最後成功備份時間（本地時區）。
- **診斷匯出遮蔽（DT-19 的一部分）**：匯出內容遮蔽 home 目錄、使用者名稱、DB 與備份路徑、runId 與秘密樣式。完整版（dry-run 預覽、秘密掃描報告）仍屬 DT-19，本版未做。
- **CI**：`.github/workflows/desktop-smoke.yml` 在 Windows、macOS 與 Ubuntu（xvfb）執行 Electron 煙霧測試（11 個案例，其中 1 個只在 Windows 執行，另有效能 spec）。`pnpm install` 不下載 Electron 二進位，只有煙霧測試會下載。Ubuntu 只當回歸檢查：Ubuntu 24.04 的 AppArmor 不讓未封裝的 Electron 使用非特權 user namespace，下載的測試二進位也沒有 setuid 的 `chrome-sandbox`，所以只有 Linux 的測試啟動參數加 `--no-sandbox`；renderer 的 `sandbox`、`contextIsolation` 與 CSP 不變，Windows 與 macOS 保留完整的 OS sandbox，產品本身不加這個參數。

## 不變的部分

沒有 schema 變更（33），沒有 migration。CLI、MCP 與 HTTP API 的既有行為不變；`/api/health` 的回應主體不變，只在請求帶有效 challenge 時多一個 proof 標頭。`start` 指令新增 `--desktop-ipc` 分支，供桌面子程序使用。

plugin、standalone 與 MCPB 的 Agent 設定沒有改動，仍使用原本的啟動方式。DT-23 的 launcher 尚未接到 Agent 設定。

## 升級

1. 本版沒有可安裝的桌面 App，沒有安裝包、簽章、公證與自動更新。開發者可執行 `pnpm test:desktop-smoke` 重現煙霧測試；它需要網路，用來下載 Electron 與官方 Node.js 的 runtime。
2. 不需要 migration，也不需要重新匯入資料。
3. 執行 `pnpm check`，確認 SQLite 沒有警告。

## 未驗證與已知限制

- **實機尚未驗收**：Windows 11 的登入項 `--background`、單例、tray、8.3 短名與 `TerminateProcess`；macOS 的 `wasOpenedAtLogin`、`mainAppService`、Dock、選單列、Gatekeeper 與簽章。以上全部待實機驗收。
- **CI 結果待確認**：撰寫本文件時，desktop-smoke 在 Windows、macOS 與 Ubuntu 的 CI 結果尚未取得，要等 PR 的 workflow 執行。
- **階段 2 gate 未通過**：`docs/desktop/desktop-v1-design-r4.md` §9.4 要求在實機上確認不開錯 DB、不雙開、不依賴瀏覽器即可修復；這些尚未確認。
- **未做的項目**：簽章、公證、安裝包、自動更新、DT-01 完整的來源偵測精靈、DT-19 完整診斷（dry-run 預覽與秘密掃描報告）、DT-24 runtime 清理，以及 Windows ACL 檢查（launcher 仍回報 `not-implemented`）。
- **runtime 類型**：依 ADR-04，App 只用 `runtimeKind` 為 `node` 的 runtime 啟動後端；其他類型以 `RUNTIME_KIND_NOT_ALLOWED` 拒絕並進入修復。
- **桌面效能數字（本機 Linux、xvfb、合成資料）**：改前與改後的啟動流程交替各量 3 輪、共 9 個樣本，冷啟動中位數改前 501 ms、改後 506 ms，修復視窗改前 530 ms、改後 562 ms，退出都約 14 ms，差異都在每次執行的雜訊內，也就是後端提早啟動在 Linux 上**沒有量得到的改善**。MANAGED 後 5 秒主程序約 155 MiB、後端約 94 MiB。冷啟動的關鍵路徑是後端子程序在送出 hello 前載入伺服器模組（約 220 ms，單一執行緒），延後載入無法縮短。Windows 與 macOS 的數字要等 CI 的 artifact。
- **Electron 版本**：殼鎖定 45.3.2。45.3.3 在 2026-11-16 才發布（npm registry 時間），未採用剛發布的版本；spike 量測的是 45.3.3，spike 的數字不直接代表殼的版本。
