# Work Intelligence 1.6.51 更新說明

日期：2026-11-17。應用程式與 plugin 版本為 1.6.51。資料庫 schema 仍為 33，沒有 schema 變更，不需要 migration。

## 摘要

本版在桌面版階段 4 之後，完成兩項工作：

- 在 App 內變更連接埠（DT-14）；
- 檔案系統風險政策（DT-08）：判定 App 的資料庫放在哪裡，並處理網路磁碟、可移除磁碟、雲端同步資料夾與硬連結。

CI 可驗證的部分已實作。Windows 11 與 macOS 的實機驗收尚未進行，仍為**待實機驗收**。

### 在 App 內變更連接埠（DT-14）

- **入口**：只在 App 內變更連接埠。修復視窗的「連接埠」區段，以及工作列的「變更連接埠…」。
- **Web 狀態頁**：系統狀態頁顯示目前位址，並有「在桌面 App 變更連接埠」按鈕。
  - 按鈕只請 App 開啟「連接埠」區段（`POST /api/desktop/open-port-settings`，每秒最多一次）。
  - 頁面會把非秘密的偏好交給 App：語言、主題、編輯器、專案頁的提示是否已關閉、側欄寬度；另外還有目前的頁面路由。只有白名單內的值會被傳遞。
  - App 只把這些值放在記憶體中，供一次使用，最久 2 分鐘。不寫入磁碟，也不寫入日誌。
- **驗證**：
  - 只接受 1024 到 65535 之間的整數。
  - 瀏覽器限制的連接埠會被拒絕：1719、1720、1723、2049、3659、4045、4190、5060、5061、6000、6566、6665 到 6669、6679、6697、10080。
  - 選擇與目前相同的連接埠時，什麼都不做。
- **已被占用或不允許**：
  - 目標連接埠已被占用時，在停止任何服務之前就拒絕。空閒檢查只是提示，實際綁定（bind）的結果才算數。
  - 作業系統不允許的連接埠會回報新的錯誤 `PORT_NOT_PERMITTED`（EACCES、EADDRNOTAVAIL）。在 Windows 上，這包括 Hyper-V 與 WinNAT 保留的連接埠範圍。
  - 這個錯誤與 `PORT_OCCUPIED_BY_OTHER` 分開。後者的提示改為指向「變更連接埠」。
- **忙碌時拒絕**：App 有其他操作執行中，或後端正在匯入（包括等待確認的上傳匯入）、備份或匯出時，變更會被拒絕。
- **流程**：
  1. 原生確認視窗。Dashboard 會在新位址重新開啟；開啟中的頁面若有未儲存的編輯，會遺失。
  2. 停止目前的服務。
  3. 在新連接埠上啟動。
  4. 以私有 IPC 與 HTTP 證明驗證新服務。
  5. 只有驗證通過後，`desired.port`、`active` 與 `lastKnownGood` 才會在同一次原子寫入中寫入設定。`lastKnownGood` 現在也會在每次驗證成功的啟動時寫入。
- **失敗時**：App 回到舊連接埠。若舊連接埠也無法啟動，App 進入修復視窗，修復視窗的「連接埠」區段仍可使用。
- **中途當機**：保留舊連接埠。
- **尚未停止任何服務就被擋下**：正在執行的後端繼續執行。
- **新位址**：成功後，App 以 `http://127.0.0.1:<新連接埠>/` 開啟 Dashboard，網址帶有一次性的 URL fragment。
  - 頁面讀取 fragment，只寫入白名單內的偏好，並立即把 fragment 從網址列移除；如果原本的路由在新位址仍存在，就回到同一頁，否則回到 Dashboard 首頁。
  - session、token 與資料庫路徑都不跨連接埠傳遞。
- **Agent**：不需要改動。dashboard 指令經由 App 取得目前的連接埠。舊連接埠的書籤會失效。

### 檔案系統風險政策（DT-08）

- **判定時機**：App 啟動時，以及選擇資料庫時。啟動時的判定與後端平行進行，不會延後 Dashboard。
- **類別**：無（none）、網路磁碟、可移除磁碟、雲端同步資料夾、硬連結，以及無法判定（unknown）。
- **判定方式**：
  - Windows：以 DriveInfo 取得磁碟類型，上限 3 秒。雲端根目錄依 OneDrive 環境變數、Dropbox 的 info.json 與 iCloudDrive 判定。位於系統磁碟且不在雲端根目錄下的資料庫，不需要啟動子程序。
  - macOS：以 mount 與 diskutil 判定，上限 2 秒。雲端根目錄為 `~/Library/Mobile Documents`、`~/Library/CloudStorage` 與 `~/Dropbox`。啟動磁碟不需要啟動子程序。
  - Linux：讀取 `/proc/mounts`。
  - 符號連結只當作證據記錄。
  - 判定失敗或逾時，結果為 unknown，而且不快取。
- **網路磁碟**：不能作為 App 的資料庫。啟動時會停止後端，App 進入修復視窗，錯誤代碼為 `DB_STORAGE_NETWORK`。重試仍會被拒絕。
- **UNC 路徑**：仍然拒絕。訊息改為說明：請先把資料庫複製到本機磁碟。
- **可移除磁碟、雲端同步資料夾與硬連結**：
  - 不提供一鍵「沿用」。使用者只能勾選同意方塊後選擇，方塊會寫明理由。
  - App 不會在這些位置更新（migrate）資料庫的 schema。
- **無法判定**：只阻擋一鍵選擇。不阻擋啟動，也不阻擋 schema 更新。系統狀態頁會顯示為提示。
- **複製到本機磁碟並改用**：資料庫位於風險位置、而且需要更新 schema 時，首次執行頁與修復頁都會提供「複製到本機磁碟並改用」。
  - 先以原生對話框確認，再檢查可用空間。
  - 以 `VACUUM INTO` 做一致的複製（透過唯讀預覽子程序），再對複本執行 `PRAGMA quick_check`。
  - 複本放在 App 的預設資料庫資料夾，該資料夾本身不能是風險位置。檔名不會覆寫既有檔案：`work-intelligence-local.sqlite`、`work-intelligence-local-2.sqlite`，依此類推。
  - 之後 App 以一般的日誌化切換改用複本，並更新複本的 schema。
  - 原始檔案不會被修改，也不會被刪除。
- **系統狀態頁**：風險以警告顯示。

## 變更

- **系統狀態頁**：新增「在桌面 App 變更連接埠」按鈕；資料庫位置的風險以警告顯示。`GET /api/system/status` 的 `desktop` 欄位新增 `activePort` 與 `storageRisk`。
- **工作列**：新增「變更連接埠…」。
- **新的 API**：`POST /api/desktop/open-port-settings`，說明見 [REST API](../rest-api.md)。
- **新的錯誤代碼**：`PORT_NOT_PERMITTED`、`DB_STORAGE_NETWORK`。

## 測試

- **單元測試**：
  - 連接埠的驗證規則、瀏覽器限制清單與變更流程的控制器（成功、失敗回復、占用、忙碌、中途當機）；
  - 偏好白名單的搬運與 URL fragment 的一次性使用；
  - 風險分類（以模擬的磁碟資訊與逾時驗證）、硬連結與符號連結的證據；
  - 複製到本機磁碟：空間檢查、`VACUUM INTO`、`quick_check`、不覆寫的檔名，以及原檔不變。
- **桌面 smoke**：連接埠變更的流程與風險資料庫的修復流程（`change-port.spec.ts`、`storage-risk.spec.ts`）。
- CI 結果待 PR 檢查完成後補上。

## 升級

照常更新即可，不需要任何手動步驟。

升級後如果資料庫位於網路磁碟，App 會進入修復視窗。請依畫面把資料庫複製到本機磁碟後再使用。舊的連接埠書籤不會再指向 App，需要改用目前的位址。
