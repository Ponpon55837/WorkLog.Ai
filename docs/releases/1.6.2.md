# Work Intelligence 1.6.2 更新說明

日期：2026-10-21。應用程式與 plugin 版本為 1.6.2；資料庫 schema 維持 30，不需 migration。

## Codex 設定與診斷

`pnpm setup:agents` 現在保留 Codex 在受管理 MCP 區塊內寫入的每工具核准設定（`[mcp_servers.work-intelligence.tools.<tool>]`），並將這些 table 移到區塊下方。區塊內其他手動修改仍會被拒絕，避免覆寫設定。

Codex hooks 偵測改用 `smol-toml` 解析 `~/.codex/config.toml`。`[[skills.config]]` 等 array table，以及含中括號的引號 header，不再使 `setup:agents` 與 `pnpm check` 無法判定 hooks 是否停用。

## API 健康狀態與連接埠

`GET /api/health` 的資料庫查詢失敗時，現在以 HTTP 503 回傳 `ok: false`。`WORK_INTELLIGENCE_PORT` 不是 1 到 65535 的整數時，API 改用預設連接埠 3210，與 `pnpm track` 及資料庫占用提示一致。設定為 `0` 也會使用 3210。

## REST 錯誤碼統一為小寫

REST API 的錯誤碼統一為 lowercase snake_case。下列九個舊碼不再回傳，也不提供舊碼別名。比對舊碼的腳本需要同步更新。

| 舊錯誤碼 | 新錯誤碼 |
| --- | --- |
| `PROJECT_NOT_FOUND` | `project_not_found` |
| `PROJECT_NAME_MISMATCH` | `project_name_mismatch` |
| `PROJECT_BACKUP_FAILED` | `project_backup_failed` |
| `PROJECT_DELETE_FAILED` | `project_delete_failed` |
| `SESSION_NOT_FOUND` | `session_not_found` |
| `SESSION_NOT_VOIDED` | `session_not_voided` |
| `SESSION_CITED_BY_PENDING_CLEANUP` | `session_cited_by_pending_cleanup` |
| `SESSION_BACKUP_FAILED` | `session_backup_failed` |
| `SESSION_DELETE_FAILED` | `session_delete_failed` |

[REST API 文件](../rest-api.md)也補充 HTTP 錯誤與 HTTP 200 搭配 `outcome`（`not_found`、`skipped`）的使用時機。

## 備份與匯出的同步阻塞門檻

`pnpm test:performance` 新增四個同步操作的門檻。測試使用 5,000 筆合成 Session，每個案例取 5 次樣本，以 p90 比較下列上限。量測期間，這些同步操作會阻塞 server 的事件迴圈。

| 案例 | p90 上限 |
| --- | --- |
| 手動備份 `createBackup` | 300 ms |
| 整份資料庫匯出 `exportTo` | 300 ms |
| 全部專案資料匯出 `exportProjectData` | 400 ms |
| 全部專案匯入預覽 `previewProjectDataImport` | 1,500 ms |

這些上限是合成測試的回歸門檻，不是所有正式資料庫或 HTTP 請求的延遲保證。

## 升級

1. 在舊版目錄執行 `pnpm check`，記下資料庫位置。執行 `pnpm db:backup` 保留額外備份。
2. 若有登入自動啟動服務，先在舊版目錄執行 `pnpm service:uninstall`。停止 Work Intelligence server，並關閉會啟動 MCP 的 Codex 與 Claude 工作階段。
3. 取得 1.6.2 原始碼後，在新版目錄執行 `pnpm install --frozen-lockfile`、`pnpm build` 與 `pnpm check`。保留資料庫檔案與 `WORK_INTELLIGENCE_DB`，確認新版仍指向相同的資料庫絕對路徑，避免新目錄的預設相對路徑建立空白資料庫。
4. 執行 `pnpm start`，確認 Dashboard 與 `/api/health` 正常。若有比對舊 REST 錯誤碼的腳本，依上表更新。
5. 重新連線 Codex 與 Claude，讓 MCP 載入新版。需要登入自動啟動服務時，依[服務指南](../service.md)重新安裝並啟動服務。

完整流程與 schema 相容性限制見[發行與升級](../release.md)。
