# Work Intelligence 1.6.47 更新說明

日期：2026-11-17。應用程式與 plugin 版本為 1.6.47；資料庫 schema 維持 33，沒有 schema 變更，也不需要 migration。

## 摘要

- **桌面版階段 3（Agent 整合）的 CI 可驗證部分**：本版實作 DT-21（Agent 寫入共用 API）、DT-22（狀態分級與 host handshake）、DT-27（Dashboard bridge），以及 DT-23 的後續項目（固定 launcher 接線）。另加上兩項 backlog：Windows ACL 預熱（a）與後端閒置記憶體（b）。**階段 3 的 gate 尚未通過**：真實 host 的 handshake、Windows 與 macOS 的行為，都待 CI 或實機確認。CI 結果：CI_PLACEHOLDER。
- **Agent 寫入共用 API（DT-21）**：新增 `packages/agent-setup`（`@work-intelligence/agent-setup`），`apps/server/src/agent-setup.ts` 改為薄的 CLI。plan 為每個檔案記錄 sha256；apply 前逐項重驗指紋，寫入前後與 rename 前都再驗一次。發現外部異動即停止（`externally-modified`），不覆蓋使用者的修改。
  - 操作日誌（`<home>/.work-intelligence-agent-setup.journal.json`，fsync 後以 rename 寫入）在第一次寫入前建立。寫入後逐項驗證。補償（compensate）只回復本次操作寫入、且內容仍是它寫入的項目，由新到舊進行；遇到第一個外部異動即停止，標記為 `needs-manual-repair`。備份會保留，只刪除本次操作建立的備份。
  - `recoverAgentSetupJournal` 在動任何檔案前先驗證 journal 的路徑（只接受已知目標與同層備份）。無法讀取的 journal 會移到 `.corrupt-<ts>`，不會刪除。
  - 每個 Agent（Codex、Claude Code、Claude Desktop）的註冊會標明來源：`desktop-managed`、`manual`、`plugin`、`mcpb` 或 `unknown`，重複註冊會被標示。plan 不會在既有註冊旁再加入第二個。Claude Desktop 的 MCPB 偵測依檔案配置推測，待實機驗收。
  - `pnpm setup:agents` 的輸出與寫入的檔案位元組不變，由 golden test（`tests/server/agent-setup-golden.test.ts`）鎖定。
- **Agent 狀態分級與 host handshake（DT-22）**：`packages/desktop-core/src/agents` 新增 MCP stdio 握手探測（送出 `initialize`、`notifications/initialized` 與 `tools/list`，含分頁、逾時與程序樹終止；Windows 的 `.cmd` 經由 System32 的 `cmd.exe` 啟動）。狀態分為：已觀察到連線、已配置待確認、需要信任或授權、外部管理、設定衝突、runtime 不相容與需要重新連線。寫入設定檔不等於已連接。
  - `apps/mcp` 在程序內第一次收到 host 的 `initialize` 時，把 clientName、clientVersion、protocolVersion、契約指紋、serverVersion 與時間記錄到 `<config dir>/agent-observations.json`。紀錄失敗不影響 MCP（fail-open）。自我測試用的用戶端不會被記錄。
  - 契約指紋（`packages/shared/src/mcp-contract-fingerprint.ts`）是每個工具的 name、inputSchema（加上 outputSchema 與 annotations）的 sha256。只有指紋與目前契約相同的觀察才會顯示「已觀察到連線」；指紋不同則顯示需要重新連線。
  - 自我測試（`WORK_INTELLIGENCE_MCP_SELFTEST=1`）不開啟資料庫、不寫入 runtime 狀態，只在 stderr 印出一行。
- **固定 launcher 接線（DT-23 後續）**：打包後的 App 在 runtime 成為 current 後寫入 `<config dir>/desktop-integration.json`（v1：version、launcherPath、runtimeRoot、appExecutable、appVersion、writtenAt）。內容未變時略過。紀錄不含資料庫路徑與使用者資料。plugin 的 `launch.mjs`、MCPB（`scripts/mcpb-launch.mjs`）與獨立版的 `work-intelligence mcp` 在紀錄有效時，優先使用固定 shim。信任規則見 ADR-39。
  - `setup:agents` 新增 launcher 目標：MCP 為 shim 加上 `["mcp"]`；hook 為加引號的 shim 加上 `claude-finalize-reminder` 或 `codex-finalize-reminder`。shim 路徑必須是絕對路徑，檔名為 `work-intelligence-launcher`（Windows 為 `.cmd`），不得含 `$`、反引號、`%`、`"`、`!`、`^`、`&` 或控制字元。Windows 只接受磁碟機代號路徑，不接受 UNC 與 `\\?\`。
  - hook 經 shim 執行時靜默，25 秒後終止（Windows 以 `taskkill /T` 終止整個程序樹），無論如何都以 0 結束，包括 spawn 拋出例外的情況。
  - MCPB 使用者設定的 `WORK_INTELLIGENCE_DB` 會經過 launcher 傳給後端。
- **Dashboard hand-off（DT-27）**：`launch.mjs dashboard`（與 `pnpm dashboard`）若已有 Work Intelligence server 回應該 port，照舊印出 URL。否則在紀錄有效時，以 `--open-dashboard` 分離啟動 App 後結束（exit 0），不會啟動 checkout 的 server。App 首次帶此旗標啟動時，在後端就緒後開啟一次 Dashboard（`--background` 也一樣）。第二個實例透過單例鎖的附加資料轉交請求。STARTING、QUIESCING、PREPARING 期間的請求會延後，並合併為一次開啟。
- **Windows ACL 預熱（backlog a）**：首次安裝時，tier-1 的 PowerShell ACL reader 在 bundle 內容檢查通過後、複製 runtime 之前啟動，路徑以 stdin 的 Base64 UTF-8 行傳入。逾時設定不變。失敗時退回一次性 reader；Constrained Language Mode 改用 tier 2。快路徑（runtime 已安裝）與 `verifyInstalled` 不做預熱，並有測試保證。日誌新增 ` acl-prewarm=<ms> ms`，效能指標新增 `firstStartAclPrewarmMs`（win32 gate 8000 ms）。
- **後端閒置記憶體（backlog b）**：RSS_PLACEHOLDER

## 不變的部分

沒有 schema 變更（33），沒有 migration。`pnpm setup:agents` 的輸出與檔案位元組不變；MCP 的工具行為不變，本版只在 `initialize` 時多一筆 fail-open 的觀察紀錄。plugin 的 manifest（`plugin.json`、`codex.mcp.json`）仍以 `node launch.mjs` 啟動，所以 Agent 啟動 plugin 本身仍需要 Node。手動 stdio 經由 `setup:agents` 的 launcher 目標則不需要 Node。

## 升級

1. 不需要 migration，也不需要重新匯入資料。
2. Agent 是否改用 launcher 目標，取決於 `pnpm setup:agents` 的 plan 預覽。請先看預覽，再套用。
3. 若 MCP 契約指紋改變，Agent 會顯示「需要重新連線」，重新連線後才會回到已觀察到連線。

## 未驗證與已知限制

- **App 設定中心尚未接上 Agent API**：桌面 App 的 UI 目前不呼叫 DT-21 的 API。
- **plugin manifest 尚未改為啟動固定 launcher**：仍是 `node launch.mjs`，因此 plugin 仍需要 Node。
- **host 的 clientInfo**：Claude Code 與 Codex 的 clientName（`claude-code`、`codex-mcp-client` 或 `codex`）依文件與實驗確認；Claude Desktop 的 `claude-ai` 未驗證。
- **Claude Desktop 的 MCPB 偵測**：依檔案配置推測，待實機驗收。
- **紀錄的信任模型**：依同一使用者威脅模型（ADR-39）。同一使用者的程序本來就能改寫 Agent 設定，因此紀錄檢查防止的是誤指向，不宣稱防禦同使用者的惡意程式。
- **Windows ACL 預熱**：真實的時間節省、PowerShell 5.1 讀取 redirected stdin 的行為（`-InputFormat None`）待 CI 確認。失敗時由一次性 reader 接手。
- **舊 plugin 的 checkout server**：在更新前，舊 plugin 的 dashboard script 仍可能自行啟動 checkout server（ADR-28 的後果）。
- **DT-24 仍是部分實作**：舊 runtime 的清理尚未證明「無現役連線」（見 1.6.45）。
- **效能數字只有 Linux**：Windows 與 macOS 的數字待 CI。

## 待實機驗收

- Windows 11：ACL 預熱的真實時間（CI 的 `firstStartAclPrewarmMs`、`firstStartAclMs`、`firstStartMs`）、PowerShell 5.1 的 stdin 行為、`.cmd` 與 `%*`／`!` 的行為，以及 hook 以 `taskkill /T` 終止程序樹。
- Windows 與 macOS：`desktop-integration.json` 紀錄與 `setup:agents` 的 launcher 目標，在真實 Agent 中的行為。
- Claude Code、Codex、Claude Desktop：實際 host handshake，以及狀態顯示為「已觀察到連線」。
- Windows 與 macOS 上 Dashboard hand-off 的冷熱啟動數字，以及後端閒置 RSS 的數字（RSS_PLACEHOLDER）。
- 以上所有項目的 CI 結果：CI_PLACEHOLDER。
