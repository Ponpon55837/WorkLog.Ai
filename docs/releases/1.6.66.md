# Work Intelligence 1.6.66 更新說明

應用程式與 Agent plugin 版本為 1.6.66。這一版沒有資料庫 schema 變更，資料庫維持 35，專案匯出檔格式與 1.6.64 相同。

## Agent 用量頁面

- Web Dashboard 在「系統狀態」旁新增「用量」頁。桌面 App 管理的 Dashboard 與 `pnpm bootstrap` 安裝的 Dashboard 都有這一頁。
- 選擇已追蹤的專案即可，不需要自己找紀錄資料夾：Claude Code 依專案位置對應 `~/.claude/projects` 底下的資料夾（含 worktree），Codex 依紀錄中的工作目錄比對，工作目錄只用來比對，不會顯示。對應不到時可用「進階：手動加入資料夾」。
- 頁面顯示回合數、工具呼叫數、Work Intelligence 呼叫佔比、各類 Token、估算的成本佔比、Work Intelligence 各操作的呼叫次數與回應字元數、估算成本最高的對話，以及其他工具的前幾名。成本佔比依假設的價格倍率估算。
- 「複製給 Agent」先預覽再複製一段摘要，只含加總數字、專案名稱與對話序號，不含路徑、資料夾名稱或對話內容。
- 解析在背景 worker 執行，上限 60 秒且可以取消；沒變的紀錄檔不重算，變大的檔案只讀新增的部分。
- 同樣的報告可以用指令取得：

```bash
pnpm usage:report --project WorkLog.Ai --since 2026-11-16T00:00:00Z
```

  可用參數有 `--project`、`--all`、`--since`、`--until`、`--json` 與 `--for-agent`。原本的 `node scripts/agent-usage-report.mjs <路徑>` 維持可用，並改為依 Work Intelligence 操作（例如 `work_get_knowledge_page_context`）分組，只讀呼叫參數的 `operation` 欄位。

## 測試

- 桌面 smoke 測試以 schema 34（1.6.63）與 schema 31 的升級樣本，模擬 App 升級後正常啟動：確認顯示「需要更新資料庫」且只有一個主要按鈕，按一次後服務執行中、schema 為最新、剛好一份升級前備份，資料筆數不變。
- CI 的打包後 smoke 步驟上限 20 分鐘，腳本本身 17 分鐘會自行停止；輸出與 App log 即時寫入檔案，失敗也會上傳，最後幾行會出現在 job 摘要。清理行程時不再結束啟動測試的行程（例如 CI 步驟的 shell 或 runner）與測試開始前就存在的行程；Windows 重用 pid 時先前可能發生這種情況。

## 升級

桌面 App 可在「設定」分頁的「更新」卡片檢查新版。依使用的安裝方式參考[更新 Work Intelligence](../user-guide.md#更新-work-intelligence)。更新 Agent plugin 後，Agent 回報 `restartRequired` 時請重新連線 Work Intelligence MCP。
