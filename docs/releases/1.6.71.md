# Work Intelligence 1.6.71 更新說明

應用程式與 Agent plugin 版本為 1.6.71。資料庫維持 schema 36，這一版不需要遷移。

## 知識頁只讀待核對段落

Agent 用單段更新（1.6.69 的 `upsertSections`／`removeHeadings`）維護知識頁時，現在可以只讀需要再看一次的段落，不必每次讀整頁加上所有新 Session。呼叫 `work_get_knowledge_page_context` 時帶 `reviewOnly: true` 即可。

段落在兩種情況下需要核對：

- 它引用的 Session 在頁面儲存後被修改、作廢或還原（和原本的 `reviewSections` 相同）。
- 有新 Session 對應到它：新 Session 與段落引用的某筆 Session 有關聯（`continues` 或 `related`，任一方向），或改過同一個檔案。

關聯的權重是 2，共同檔案是 1，平均分給證據指向的段落。指向超過 3 段的證據（例如各段都有 Session 改過的 CHANGELOG 或 package.json）太常見，不用來對應。每筆新 Session 最多對應到得分最高的 3 段，只有弱證據的列為對不到段落。頁面已經引用的新 Session 不會對應到引用它的那一段。對應只看關聯與檔案，不比對文字，所以同一份資料每次結果相同。

要核對的段落超過頁面段落數的一半、這些段落全文合計超過 4,000 字，或回應不會比全頁讀取小時，回應改標 `use_full_read`，不帶段落與 Session，請 Agent 改讀全頁。所以只讀待核對段落不會比全頁讀取花更多字數。

回應內容：

- `review`：`sections`（有段落要核對）、`new_sessions`（沒有段落要核對，但有新 Session 對不到段落）、`none`（沒有要核對的，回應很小）、`full_rewrite`（頁面還沒寫過或使用者要求更新，請讀全頁）或 `use_full_read`（大部分段落都要核對，請讀全頁）。
- `sections`：要核對的段落全文，附 `reasons`（來源原因代碼，以及 `new_session_linked`、`new_session_shared_files`）、`changedSources` 與 `newSessionIds`。
- `otherSections`（其餘段落的標題與字數）與 `size`（`sectionCount`、`maxSections`、`contentChars`、`maxContentChars`），讓 Agent 知道版面和剩下的空間。
- `sessions`：這些段落背後的 Session 預覽，每筆只列一次。`unmappedSessions`：對不到段落的新 Session，只列 id、標題與完成時間。
- `checkedThroughCandidate`：最後一筆處理到的新 Session，它之前的新 Session 都已列出；處理完可以拿它呼叫 `work_mark_knowledge_page_checked`。`truncated: true` 表示還有沒列出的，處理完再讀一次。
- `reviewToken`：和聚焦讀取一樣沿用頁面既有的涵蓋範圍，用於單段更新。

`reviewOnly` 不能和 `query` 或 `headings` 一起帶，會以參數錯誤拒絕。

在測試用的合成資料上（8 段的頁面、1 段需要核對、6 筆新 Session），只讀待核對段落的回應是 2,822 字，一般的 `review` 讀取是 8,106 字；沒有要核對時是 1,007 字。另一份模擬長期專案的合成頁面有 12 段、每段引用 10 筆 Session，發版檔案分散在各段：3 筆新 Session 時是 5,509 字對 14,659 字，8 筆時是 7,059 字對 16,014 字；新 Session 分散到 8 段時回 `use_full_read`，1,216 字。

## 新 Session 與有變動來源不再重複列出

`review` 模式下，一筆 Session 同時是新 Session 又是有變動的引用來源時，以前會列兩次並占用兩次 Session 預算。現在只列一次，放在新 Session 之中，`reasons` 為 `["new", "source_changed"]`。Session 的欄位因此由單一的 `reason` 改為陣列 `reasons`。涵蓋範圍仍算到最後一筆顯示的新 Session。

有變動的引用來源只有仍屬於這個頁面專案時才會給預覽。

## 升級

桌面 App 可在「設定」分頁的「更新」卡片檢查新版。依使用的安裝方式參考[更新 Work Intelligence](../user-guide.md#更新-work-intelligence)。這一版改了 MCP contract 文字，MCP 相容性 ID 因此改變：升級後已連線的 Agent 會收到 `restartRequired`，請重新連線 Work Intelligence MCP；更新 Agent plugin 後也一樣。
