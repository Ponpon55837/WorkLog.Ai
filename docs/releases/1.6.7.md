# Work Intelligence 1.6.7 更新說明

日期：2026-11-07。應用程式與 plugin 版本為 1.6.7；資料庫 schema 從 30 升到 31，首次啟動會先備份再自動套用 migration。升級後需要重新連線 Codex／Claude 的 MCP。

## 後端效能

- 備份、整庫匯出、專案資料匯出與匯入預覽改在獨立的 worker 執行，執行期間 API 與畫面不再卡住；啟動後的自動備份延到 60 秒後。
- 系統狀態頁查詢登入服務改為非同步，結果快取 30 秒；SQLite 頁面快取加大到約 16 MB。
- Agent 讀取工作記錄只更新「Agent 讀取紀錄」區塊，不再讓整個畫面重新抓資料（schema 31）。
- Graph 只讀取畫面會用到的欄位與 Session，結果不變，記憶體用量明顯下降。
- Knowledge 過時判斷改用檔案索引，`work_get_context`、`work_recall`、Knowledge 搜尋與首頁提醒約快 2 倍，結果不變。
- `pnpm db:maintain` 之後，年報的決策統計不再變慢；維護流程只執行一次 `ANALYZE`。
- 首頁提醒的來源比對改用固定大小的摘要；被隱藏或稍後提醒的項目在來源有新增、更新、刪除或作廢時仍會重新出現。
- finalize 的相關未結項提醒改在交易完成後才查詢；提醒查詢失敗時仍回報已保存的 Session。

## 修正

- 舊資料的 changed files 欄位為 JSON `null` 時，metadata 補齊預覽不再出錯。

## 行為變更

- `pnpm db:restore` 移除 `--force`：資料庫被 server 或 Agent 開啟時一律停止還原。

## 開發與測試

- CI 改為三個瀏覽器平行執行 E2E，並與跨平台品質檢查同時開始，總時間約從 23 分鐘降到 6.5 分鐘。
- 效能檢查對第一次超標的案例會再量一次，門檻不變。
- Storage 覆蓋率改為涵蓋全部原始碼，27 個高風險服務設逐檔門檻。

## 升級

1. 在舊版目錄執行 pnpm check 並記下資料庫位置；可先執行 pnpm db:backup。
2. 取得 1.6.7 原始碼後執行 pnpm bootstrap（或 pnpm install --frozen-lockfile、pnpm build 與 pnpm check）。
3. 若已安裝登入自動啟動服務，執行 pnpm service:restart，確認輸出「服務已在執行 1.6.7」。首次啟動會建立 migration 前備份並升級到 schema 31。
4. 重新連線 Codex／Claude 的 MCP；舊連線在 schema 升級後會回報需要重新連線。

完整流程與 schema 相容性限制見發行與升級指南（docs/release.md）。
