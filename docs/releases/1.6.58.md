# Work Intelligence 1.6.58 更新說明

日期：2026-11-19。應用程式與 plugin 版本為 1.6.58。資料庫 schema 仍為 33，沒有 schema 變更，不需要 migration。

## 摘要

本版處理 Windows 打包版 1.6.57 實際看到的三個問題。

- 「設定」分頁新增「登入時自動啟動」開關（Windows 與 macOS）。設定完成後可以隨時開關；頁面只送出開或關，開啟仍以使用者自己按下開關作為同意。卡片會顯示系統實際狀態，與設定不一致時會說明原因（例如在系統的啟動項目設定中被關掉，或 macOS 還在等你核准）。文字有繁體中文與英文，不出現任何指令。
- Web「系統狀態」在桌面 App 管理模式下，「登入自動啟動」卡片改為顯示 App 自己的登入啟動狀態，以及 App 實際使用的資料庫與備份目錄。舊的工作排程服務資訊只在偵測到它仍存在時才出現，並指向 App 的「狀態」分頁。
- Web「MCP 連線」不再顯示 0：後端與 Agent 的 MCP 改用同一個以 App runtime 根為準的 lease 範圍。

升級不需要任何手動步驟。設定、資料庫與備份都不會因為升級而改變。Windows 11 與 macOS 的實機驗收尚未進行，仍為待實機驗收。

## 修復項目

- **登入自動啟動開關。** 設定值以既有的原子寫法寫入設定檔後才呼叫系統的登入項目；寫入失敗時不會動到系統。實際狀態讀自系統，不是讀設定檔。
- **系統狀態的卡片與路徑。** 舊卡片的資料庫、備份與日誌路徑是用 repo 預設規則推算的，桌面後端的環境是白名單，沒有 `WORK_INTELLIGENCE_DB`，所以顯示 checkout 內的 `data`、`service\work-intelligence.task.xml` 與 `logs\server.log`。這只是顯示錯誤：後端實際開啟的是 App 傳入的資料庫，沒有兩份資料庫同時被使用。現在卡片使用後端實際的資料庫與備份目錄。
- **MCP 連線數。** lease 目錄原本由各自 runtime 根目錄的雜湊決定，而後端與 Agent 的 MCP 各自從不同的 `runtimes/<id>` 執行，彼此看不到。App 的 launcher 現在替兩者設定同一個範圍（環境變數 `WORK_INTELLIGENCE_APP_LEASE_SCOPE`，值為 App 的 runtime 根）。沒有這個變數的舊 runtime 或舊 launcher 仍用原本的規則；舊的 lease 目錄不遷移，因為 lease 只存活數十秒。
- **Agent 連線證據。** Web「系統狀態」改用與 App「Agent」分頁相同的共用程式讀取 `agent-observations.json`，兩邊的主機客戶端與「目前／過期／無」狀態一致。登入啟動狀態在系統於 App 之外被改動時會重新送給 Web 頁面；設定分頁的開關在變更失敗後會恢復可操作。
- **清除無用程式碼。** 移除沒有人使用的訊息文字、更新連結 schema、兩個 storage 輔助函式、三個共用常數，以及 `blockingTab`、`recognised`、`other-sources-present` 欄位。設定檔保留 `active.runtimeVersion` 與 `active.serviceOwner`，因為 1.6.57 讀不到這兩個欄位會拒絕該檔。

## 測試

- 新增 CI 守門：修復通道四方對照（preload、`REPAIR_CHANNELS`、main handler、頁面呼叫）、設定檔每個欄位都有讀寫、每個 shell 訊息鍵都有使用、產品之間交換狀態的檔案登錄表（寫入端與讀取端須在不同檔案）、Web 全部程式碼的「不顯示指令」檢查。

- `tests/shared/mcp-runtime.test.ts`：後端與 MCP 的 root 不同但屬同一個 App 時，後端看得到 MCP 的 lease；沒有共同範圍時看不到；不同 App 安裝互不干擾。
- `tests/desktop-core/launcher-lease-scope.test.ts`：launcher 對 `serve` 與 `mcp` 設同一個範圍，hook 不設。
- `tests/desktop-core/login-item-status.test.ts`、`login-item-controller.test.ts`：Windows 與 macOS 的系統狀態判讀、不一致說明、只收 boolean 的 IPC、先寫設定再套用、寫入失敗不動系統。
- `tests/server/desktop-api.test.ts`、`tests/web/utils/labels-status.test.ts`：狀態 API 回報實際資料庫、備份目錄與登入項目。
