# Work Intelligence 1.6.63 更新說明

應用程式與 Agent plugin 版本為 1.6.63。資料庫 schema 從 33 升到 34，首次啟動時會先自動備份，再執行 migration。

## 知識頁

- **沒看到的 Session 不再算成已涵蓋。** `work_get_knowledge_page_context` 會回傳 `reviewToken`。`work_save_knowledge_page` 帶上它時，涵蓋範圍只算到這次讀取實際列出的最後一個 Session。context 截斷時被略過的 Session，以及讀取後才完成的 Session，保存後仍是新資料，下次檢查會再列出。
- **不再覆蓋較新的版本。** Agent 帶 `reviewToken`、Web 編輯帶 `baseVersion` 儲存時，如果頁面在讀取或開始編輯之後已被存過，會回 `version_conflict`，不寫入。Web 編輯框保持開啟並保留草稿，提示衝突的版本。
- **重送內容不同時明確拒絕。** 同一個 idempotencyKey 帶不同的段落內容重送，回 `idempotency_conflict`，不寫入。之前會回報成重複請求並丟掉新內容。
- 沒帶 `reviewToken` 的 Agent 儲存維持原本行為，並在回應附上 `warnings` 提醒改用新流程。
- 維持原本行為：Web 手動編輯會把儲存前完成的 Session 全部算成已涵蓋；Agent 讀取後使用者才提出的更新請求，Agent 儲存時一併清除。

## 資料庫

`knowledge_pages` 新增兩個可為空的欄位，記錄 Session 涵蓋位置。既有頁面維持目前的涵蓋範圍。schema 31 到 33 的匯出檔仍可匯入。

升級後，Agent 回報 `restartRequired` 時請重新連線 Work Intelligence MCP。1.6.63 之前的版本無法開啟升級後的資料庫（`DATABASE_SCHEMA_VERSION_TOO_NEW`）；需要退回時，請還原升級前的自動備份。

## 測試

- 新增知識頁維護的確定性測試：與頁面無關的 Session、引用來源變更、作廢與還原、字元預算截斷、重送、讀取到保存之間的來源變更，以及保存後頁面與版本的一致性。

## 升級

桌面 App 可在「設定」分頁的「更新」卡片檢查新版。依使用的安裝方式參考[更新 Work Intelligence](../user-guide.md#更新-work-intelligence)。
