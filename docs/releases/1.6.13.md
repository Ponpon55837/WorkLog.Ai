# Work Intelligence 1.6.13 更新說明

日期：2026-11-09。應用程式與 plugin 版本為 1.6.13；資料庫 schema 維持 32，不需要 migration。

## 可攜式 JSON 雙向匯入

兩台電腦（例如 Mac 與 Windows）都記錄同一個專案、用「匯出專案 JSON → 另一台匯入」同步時，不再出現大量衝突。

- **自動沿用本機路徑**：相同專案 ID 已存在但根路徑不同時，匯入會改用這台電腦的根路徑（含 handoff 來源路徑），不再讓整個專案與全部子資料一起衝突；換電腦匯入不必再加 `--remap-root`。
- **新的合併策略「較新者優先」**（Web 預設；CLI `--strategy newer-wins`；REST `strategy: "newer-wins"`）：兩邊都有、內容不同的可變更資料（Session、決策、未結項、Knowledge、知識頁、候選、報告請求等），依該資料自己的時間欄位取較新者；本機較新的資料一律保留；只追加的歷史紀錄與本機專案資料不會被覆寫。預覽會列出「將更新」與「保留本機」的筆數。原本的「只新增」（`merge`，CLI 預設）仍不覆寫既有資料，但本機較新的列不再算成衝突。
- **衍生欄位不算差異**：只差在各電腦自己計算的值時不再是衝突，包括 Session 的 `redaction_count`、只因新遮蔽規則而不同的文字、changed-file 來源合併順序、關注項目的隱藏／延後狀態，以及報告摘要的 `is_current`（匯入後依最新摘要重算）。本機已有完全相同的列時，即使上層資料衝突也直接略過；既有 Session 或 Knowledge 內容衝突時，不再擋住它新的子資料。
- **Windows 路徑大小寫**：handoff 來源路徑只差在 Windows 大小寫或分隔符號時視為同一路徑（Windows 資料庫的根路徑存成小寫，handoff 路徑保留原大小寫），不再算成路徑衝突。
- **知識頁版本撞號並存**：兩台電腦各自存了同一頁的同一版本號時，該頁所有版本依建立時間重新編號後全部保留，頁面版本計數器移到最新版本。
- **衝突依原因彙總**：預覽依資料表、類別（路徑、匯入資料較新、內容不同、唯一識別值、依賴連帶）與原因列出筆數與範例 id，不再只列前 100 筆。
- **跨專案報告隨專案匯出**：單一專案匯出會一併帶入引用該專案 Session 的跨專案報告請求、摘要與 metadata 回補請求，刪除專案後重新匯入不會遺失。

## 效能

匯入預覽的唯一識別值查詢改為每個連線只準備一次 SQL，5,000 筆 Session 加 50,000 筆事件匯入到空資料庫的預覽 CPU 時間約少 19%。

## 升級

1. 取得 1.6.13 原始碼後執行 pnpm bootstrap（或 pnpm install --frozen-lockfile、pnpm build 與 pnpm check）。
2. 若已安裝登入自動啟動服務，執行 pnpm service:restart，確認輸出「服務已在執行 1.6.13」。
3. 不需要重新連線 MCP；MCP 工具與 Agent 契約沒有變更。兩台電腦都要升級到 1.6.13，匯入時才會使用新的合併方式。

完整流程見發行與升級指南（docs/release.md）。
