# Work Intelligence 1.6.79 更新說明

應用程式與 Agent plugin 版本為 1.6.79。資料庫升到 schema 39，升級時自動備份。Agent 不需要重新連線 MCP。

## 同時進行的多段工作不再互相混列

結案回條的 `unreportedKnowledge` 會列出這段工作讀過、還沒回報的 Knowledge。同一個 Agent 用戶端同時進行兩段工作（例如開兩個視窗）時，先結案的那一段會列到另一段讀過的 Knowledge，另一段反而什麼都沒有。

這一版改為依 MCP 連線歸屬：

- 每個 MCP server 程序有自己的連線識別，讀取 audit 會記下它。
- 結案時只計算同一條連線的讀取，工作起點取這條連線在該專案的上一次保存。
- A 讀 a1、a2，B 讀 b1、b2，不論誰先結案，A 只列 a1、a2，B 只列 b1、b2。
- 沒有連線識別的呼叫（REST、舊版 MCP 程序）維持原本只看專案、用戶端與時間的算法。

## 資料庫

schema 39 在 `agent_read_audit` 新增可為空的 `connection_id` 欄位。這張表只存在本機，不在匯出範圍；升級前的資料列沒有連線識別，不會被列入。

## 已知限制

- Claude Desktop 可能讓多個對話共用一條 MCP 連線，這些對話的讀取仍然共用同一個連線識別，可能互相混列。
- MCP server 換成新版（launcher 更換子程序）之前的讀取不會計入，結果會少列而不是多列。
