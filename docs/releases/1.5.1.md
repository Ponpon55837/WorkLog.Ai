# Work Intelligence 1.5.1 更新說明

日期：2026-10-11。應用程式與 plugin 版本為 1.5.1；資料庫 schema 維持 30。

## 報告來源與 Agent 讀取

建立整理請求時保存期間內所有可用來源 ID，後續按固定順序分頁讀取。新增超過 200 筆記錄後，舊請求仍可取得原來源。作廢或暫停來源維持政策限制，coverage 會分開標示請求保存數、目前可用數、不可用數、選取頁數與目前期間統計；證據分頁只使用這一頁的來源。

MCP 的 work_get_report 與 work_get_report_context 預設使用 agent 預覽，完整 JSON 文字預算為 24,000 字元，可設定 12,000–60,000。預覽保留統計、來源指標與明確省略資訊，不重複傳送完整 Session／completedWork／raw handoff。整理前仍須讀取完整來源 Session；view: full 可明確取得原完整欄位並略過預算。REST 基本報告仍保留完整欄位。字元上限不是 tokenizer 或帳戶計費 token 數。

## 閱讀與寫作

AI 整理卡片先確認狀態，載入失敗時顯示錯誤；確認沒有整理版後才呈現空狀態。載入／錯誤時禁止建立請求。已保存的引用數與目前期間統計各自標示，長摘要可展開；不自動改寫歷史報告。

新增英文與繁體中文寫作 skill，依輸出語言按需讀取。成果先寫、事實只放一個主要段落，涵蓋範圍集中說明；維持引用、數字及驗證狀態。英文借用 ASD-STE100 的清楚表達原則，繁中採專案用語指南，兩者皆不宣稱通過 STE 合規認證。正式 STE 要求仍須另外核對完整標準及核准詞彙。

未結項與整理清單採用穩定項目 ID，即時更新後保留捲動位置。一般 Agent context 的待處理報告只提供最多 5 個來源指標及額外數量，完整請求來源仍保留。

## 升級

先備份資料，更新並建置後重啟服務、重新連線 MCP。契約新增預覽與分頁參數，舊 client 要完整回應時需傳 view: full。

```bash
pnpm db:backup
git pull --ff-only
pnpm install --frozen-lockfile
pnpm build
```

本次不增加資料表／migration、不批次改寫既有來源或報告。健康 MCP 的 doctor 不再附上無關的重連建議。
