# Work Intelligence 1.6.75 更新說明

應用程式與 Agent plugin 版本為 1.6.75。資料庫升級到 schema 37，升級時會先備份再自動遷移。

## 刪除自訂知識頁

不再需要的自訂知識頁現在可以在 Web UI 刪除。

- 在「知識」分頁打開一個自訂知識頁，按「刪除知識頁」。確認視窗會寫出一併刪除的歷史版本數，刪除後無法復原。
- 三個預設頁（架構與慣例、進行中的工作與未結項、常見陷阱）沒有這個按鈕，REST 也會拒絕。
- 頁面、全部歷史版本、待處理的更新請求，以及這一頁在注意事項裡的隱藏或延後設定，會在同一個交易中一起刪除。之後它不會再出現在知識頁清單、搜尋、維護提醒與 `work_get_context`。
- 之後可以用同一個 slug 再建立一頁，會是一個全新的空白頁。
- Agent 沒有刪除知識頁的工具。Agent 讀到一個所有段落都是「資料不足」的自訂頁時，回應會另帶 `emptyPageHint`，提醒 Agent 告訴你可以在 Web UI 刪除。預設頁、已要求更新的頁面不會出現這個提示。
- REST：`DELETE /api/knowledge-pages/:id`，body 為 `{ "confirm": true }`。預設頁回 409 `knowledge_page_default`，找不到回 404 `knowledge_page_not_found`。`GET /api/knowledge-pages/:id/versions` 另帶全部版本數 `versionCount`。

## 匯入較早的匯出檔不會把刪掉的頁面加回

刪除前匯出的 JSON 檔裡仍有這一頁。如果直接合併匯入，頁面會被當成本機沒有的新資料加回。

這一版新增 `knowledge_page_deletion_audit` 資料表，只記錄刪除時間、頁面 id、專案 id 與筆數，不含標題、slug 或內容。匯入時（「只新增」與「較新者優先」都一樣），匯入檔裡同一個 id 的頁面與它的注意事項設定列為「已在本機刪除」衝突，版本列為相依衝突，都不寫入。匯入預覽、Web 的備份區與 `pnpm db:import --dry-run` 都會顯示這些衝突。

要注意的限制：

- 刪除只記在這台電腦。另一台電腦上的同一頁不會因此刪除；那台電腦也要自己刪。
- 刪除紀錄不會匯出。另一台電腦之後用同一個 slug 新建的頁面是不同的 id，照常匯入。
- 刪除前不會另建備份。需要找回時，只能還原刪除前的資料庫備份。
- 永久刪除的 Session 目前沒有同樣的保護。

## 拆頁前先整理

知識頁接近上限（11 段或 7,200 字）時，Agent 與 Web 的建議改成先整理：

1. 先刪掉已不再回答頁面問題的內容，例如已完成的項目，或被後來工作推翻的事實。這是正常的維護。
2. 整理後仍放不下，才問你要不要把幾段移到自訂知識頁。

仍然成立的文字照樣不會為了騰出空間而刪減或合併。段數與字數上限不變。這次改了 `splitWith`、`page_limit_exceeded` 的原因、知識頁 contract、兩個知識頁工具的說明、兩份 skill 的知識指南，以及 Web 的上限提示（繁體中文與英文）。Agent 開始工作前固定要讀的文字量沒有增加，仍是 42,249（上限 42,250）。

## 升級

桌面 App 可在「設定」分頁的「更新」卡片檢查新版。依使用的安裝方式參考[更新 Work Intelligence](../user-guide.md#更新-work-intelligence)。資料庫會從 schema 36 遷移到 37，遷移前自動備份；schema 31 到 36 的匯出檔仍可匯入。這一版改了 MCP contract 文字，MCP 相容性 ID 因此改變：升級後已連線的 Agent 會收到 `restartRequired`，請重新連線 Work Intelligence MCP；更新 Agent plugin 後也一樣。
