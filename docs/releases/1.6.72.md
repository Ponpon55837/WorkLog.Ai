# Work Intelligence 1.6.72 更新說明

應用程式與 Agent plugin 版本為 1.6.72。資料庫維持 schema 36，這一版不需要遷移。

## 知識頁接近上限時建議拆頁

每個知識頁最多 12 段、段落內容合計 8,000 字。以前頁面寫滿後，Agent 只能刪減既有文字騰出空間。現在頁面接近上限時，讀取與儲存的結果會建議把段落移到自訂頁面。上限本身沒有放寬，伺服器也不會自己拆頁。

「接近上限」的判定：

- 段數達 11 段（只剩 1 段空位），或
- 段落內容合計達 7,200 字（8,000 字的 90%）。剩下的 800 字大約是一段平均長度（8,000 ÷ 12），再加一段很可能就會被拒絕。

兩者任一成立時，下列結果另帶 `size` 與 `splitSuggestion`：

- `work_get_knowledge_page_context` 的完整讀取、聚焦讀取（`query`／`headings`）與只讀待核對段落（`reviewOnly`）。只讀待核對段落原本就有 `size`，只多 `splitSuggestion`。
- `work_save_knowledge_page` 的完整儲存、單段更新回條與同一個 `idempotencyKey` 的重試。

`size` 是 `sectionCount`、`maxSections`、`contentChars`、`maxContentChars`。`splitSuggestion` 有三個欄位：

- `near`：`sections` 和／或 `content`，指出接近哪個上限。
- `headings`：建議移到自訂頁面的段落，依字數由大到小，最多 3 段，而且不會是全部段落。
- `splitWith`：給 Agent 的一句指引，指向 `work_request_knowledge_page_update`。

沒接近上限時這些欄位都不出現，回應大小和以前相同。在測試用的 12 段合成頁面上（兩個上限都接近），提示讓回應多 221 字：只讀待核對段落 8 筆新 Session 時是 7,280 字，改讀全頁的 `use_full_read` 回應是 1,437 字，仍在原本的回應大小上限內。

Agent 收到提示後先問使用者。使用者同意後，用 `work_request_knowledge_page_update` 建立自訂頁面（新的 `slug`、`title` 與 `question`），把段落存到新頁，再用 `removeHeadings` 從原頁移除，不刪減原有文字。

## 超過上限的錯誤指向拆頁

單段更新合併後超過上限時，`page_limit_exceeded` 的 `reason` 改為建議把段落移到自訂頁面，並附上合併後頁面的 `splitSuggestion`。整頁 `sections` 超過 12 段或 8,000 字的參數錯誤訊息也改為指向自訂頁面。合併後沒有任何段落時，訊息維持請保留至少一段。

## Web 顯示用量與建議

「知識」頁的知識頁與編輯視窗在頁面接近上限時，顯示目前的段數與字數，以及建議移到自訂頁面的段落。編輯時會隨內容即時更新；超過上限時提示儲存會被拒絕。提示有繁體中文與英文。

## 共用的判定

上限、門檻與挑選建議段落的計算都在 `@work-intelligence/core` 的 `knowledgePageLimits`，儲存、參數驗證、MCP 與 Web 共用同一份。計算只掃描段落一次，同時得到總字數與最大的幾段，不增加資料庫查詢。

## 升級

桌面 App 可在「設定」分頁的「更新」卡片檢查新版。依使用的安裝方式參考[更新 Work Intelligence](../user-guide.md#更新-work-intelligence)。這一版改了 MCP contract 文字，MCP 相容性 ID 因此改變：升級後已連線的 Agent 會收到 `restartRequired`，請重新連線 Work Intelligence MCP；更新 Agent plugin 後也一樣。
