# Work Intelligence 使用手冊

Work Intelligence 是本機優先的工作記憶工具。一般使用者透過桌面 App 操作：App 視窗提供狀態、Agent、設定、資料與診斷等分頁。App 內的本機服務同時提供 Web 介面、REST API，並供 Codex／Claude Code 使用本機 MCP server。只有你明確設為「記錄中」的專案才會被讀取與保存。

本手冊先說明桌面 App 的操作。命令列步驟放在標示「給開發者與命令列使用者」的段落中，一般使用時可以略過。

## 給開發者與命令列使用者：安裝與正式模式

> **對象：開發者與習慣在終端機工作的人。** 桌面 App 的安裝方式見 [README](../README.zh-TW.md#下載與安裝)，不需要本節。

需求：Node.js 22.16 以上的 22.x 或 24 以上（建議 Node.js 24；23.x 沒有 FTS5，不支援）與專案指定版本的 pnpm。請在 WorkLog.Ai 專案根目錄執行：

```sh
pnpm install
pnpm build
pnpm start
```

預設在 <http://127.0.0.1:3210> 開啟 Web UI；REST API 也在同一個連接埠，例如 <http://127.0.0.1:3210/api/health>。終端機保持執行，按 `Ctrl+C` 停止。開發時才使用 `pnpm dev`；開發模式的 Web 使用 5966，API 使用 3210。

第一次從 checkout 設定時，也可以執行 `pnpm bootstrap`，由它安裝相依套件、建置，並預覽 Agent 與登入自動啟動的設定。確認後才會寫入全域設定，完成後用 `pnpm start` 啟動。

第一次檢查環境可執行：

```sh
pnpm check
```

請使用 `pnpm check`（舊名稱 `pnpm run doctor` 仍可使用），不要使用 `pnpm doctor`：pnpm 11 將 `doctor` 保留為套件管理器自己的命令，`pnpm doctor` 不會執行 Work Intelligence 診斷。

資料預設放在 `data/work-intelligence.sqlite`，也可設定 `WORK_INTELLIGENCE_DB` 指定位置。常用設定如下：

| 環境變數 | 用途 |
| --- | --- |
| `WORK_INTELLIGENCE_DB` | 共用 SQLite 檔案位置，API、MCP、CLI、`pnpm check` 與登入服務用同一條規則解析：相對路徑以 repo 根目錄為基準（不是目前所在資料夾）；不需要 checkout 的獨立套件則以 `~/.work-intelligence`（可用 `WORK_INTELLIGENCE_CONFIG_DIR` 改目錄）為基準 |
| `WORK_INTELLIGENCE_PORT` | Web 與 API 共用的本機連接埠，預設 `3210` |
| `WORK_INTELLIGENCE_BACKUP_DIR` | 備份目錄。命令列模式預設為資料庫旁的 `backups/`；桌面 App 模式預設為 `~/.work-intelligence/backups/`（App 的「設定」分頁可更換）。相對路徑以資料庫所在資料夾為基準，API、MCP、CLI 與 doctor 會指向同一個位置 |
| `WORK_INTELLIGENCE_BACKUP_KEEP` | 手動備份保留份數，預設 3；自動備份另行保留 3 份 |
| `WORK_INTELLIGENCE_BACKUP=off` | 停用每日自動備份 |

設定 MCP 與全域保存提醒 hook 的方式見[連接 Agent](agent-setup.md)。MCP 使用 stdio，由 Codex／Claude 分別啟動；它不使用 Dashboard 的 HTTP 連接埠。

也可以在 build 完成後執行 `pnpm setup:agents`，預覽 Codex／Claude Code 的 MCP、user-level skill 與保存提醒 hook 設定。互動終端輸入 `yes` 才會先備份並套用；詳細內容見[Agent 設定指南](agent-setup.md)。

若希望登入電腦後自動啟動正式模式，可使用 `pnpm service:install`；預覽服務設定內容並確認後，會安裝目前使用者的登入服務。服務狀態與移除方式見[登入自動啟動服務](service.md)。

## 第一次使用

使用桌面 App 時，第一次開啟會先顯示首次執行頁：

- **開始使用**：按「使用預設設定開始」就會建立資料庫並開啟 Dashboard。
- **沿用既有資料**：App 找到既有的資料庫時，會列出它的專案數，可以選「沿用這份資料」。
- **完成後**：頁面會提示下一步「設定 Agent」（見[連接 Agent](agent-setup.md)）。
- **升級的安裝**：由舊版升級、已有設定的 App 不會出現這個頁面。

接著：

1. 在左側選單開啟「專案」，選「加入專案」，選擇或輸入 workspace 路徑。
2. 新增專案預設為「未註冊」。只有你明確將狀態切換為「記錄中」，Work Intelligence 才會讀取該專案允許範圍內的 handoff、Git 或來源檔案並保存工作記錄。
3. 依[連接 Agent](agent-setup.md)註冊本機 MCP，並在 Agent 對話中確認可連線。
4. 開工前可請 Agent 查詢 Work Intelligence 的相關工作與 Knowledge；完成後請它保存本次工作。

`paused`、`ignored`、`unregistered` 專案不會被讀取或記錄。Agent 不能代替你把專案切換為「記錄中」。

### 用命令列加入並開始記錄

不想開網頁時，可以在終端機執行：

```bash
pnpm track <資料夾> [--name <名稱>] [--yes]
```

- 相對路徑以你執行指令的目錄為基準；`--name` 沒有指定時使用資料夾名稱。
- 命令會先預覽專案名稱、路徑與狀態變化（例如「已暫停 → 記錄中」），並說明「記錄中」的意思，再詢問 `[y/N]`，預設為否。確認後才加入專案並設為「記錄中」。
- 專案已在記錄中時不會寫入任何東西。若資料夾與其他專案的根目錄重疊，預覽會列出警告，但仍可繼續（與 Web 的「加入專案」一致）。
- 非互動終端沒有 `--yes` 時只顯示預覽；`--yes` 略過確認，請確認路徑無誤再使用。
- 這個命令只能由你在終端機執行，Agent（MCP）沒有對應的能力。Web 已開啟時會自動更新，不必重新整理；已連線的 Agent 下次讀取專案狀態時就會生效，不需要重新連線 MCP。

### 永久刪除專案資料

在「專案 → 專案清單」點選專案旁的垃圾桶按鈕，閱讀刪除範圍並輸入完整專案名稱，才可確認永久刪除。WorkLog 會先建立並驗證一份完整 SQLite 備份；備份失敗時不會刪除。完成後會顯示備份檔名。

「專案 → 刪除紀錄」會列出刪除時間、專案 id 與各類資料的刪除筆數。這份唯讀紀錄不保存專案名稱、路徑或已刪除的內容。

刪除會移除中央資料庫中該專案的工作記錄、handoff、Evidence、Knowledge、稽核與搜尋資料，以及引用目標 Session 的共享請求和報告。專案資料夾與檔案不會被刪除。刪除前備份是整份資料庫快照，並依手動備份的保留規則管理；它可透過 `pnpm db:restore <備份檔.sqlite>` 還原，但還原會取代目前整份資料庫。MCP 不提供專案刪除工具。

**刪除後資料仍存在於備份中**：刪除前備份，以及刪除前建立的自動、手動、migration 與維護備份，都仍然包含這個專案的完整內容，直到它們依保留規則被輪替掉為止。若需要讓資料立即無法復原，請在確認不再需要後，自行刪除 `backups/`（或 `WORK_INTELLIGENCE_BACKUP_DIR`）中這些備份檔，以及先前匯出的 `.sqlite`／JSON 檔。

## 日常流程

- **開工前**：描述任務，請 Agent 查詢相關過往工作或指定檔案的紀錄；遇到錯誤時也可直接貼上錯誤訊息讓它檢索。
- **工作中**：照常使用 Agent。Work Intelligence 不會替 Agent 推測驗證結果，也不會自動把 Knowledge 候選寫成正式 Knowledge。
- **完成時**：Agent 會先核對與本次工作相關的未結項，只有確認完成才結案；被本次新未結項明確取代的舊項目會標為「不再需要」，並連到取代它的 Session。證據不足就保留未處理，保存後也會提醒仍相關的項目。請 Agent 保存這次工作。每筆 Session 會分開保存成果、範圍、決策、驗證與狀態／未結項。
- **回顧時**：到「工作歷程」搜尋 Session，或到「工作知識」檢視已接受的決策、模式、注意事項、流程與技能。

## 報告與 Knowledge

「工作報告」支援日、週、月、季、年與自訂日期區間；統計依已保存的 Session 計算，AI 整理會保留來源 Session。可以匯出 Markdown 或 JSON。若請 Agent 整理報告，Web 會在請求完成後更新結果。

在「工作知識」可以審查 Agent 提出的候選。你可以先修改再接受，也可以明確[請 Agent 處理待確認項目](#請-agent-處理待確認項目)。候選經審查接受後才會成為 Knowledge。Knowledge 可以編輯、封存、恢復及查看變更紀錄；封存不會刪除資料。

更完整的資料格式與搜尋行為見[架構與資料契約](architecture.md)及[MCP 工具參考](mcp-tools.md)。

## 各頁面功能

### 概覽的「需要處理」

- 有待處理項目時，「需要處理」排在統計卡片之前；點「待處理」卡片會捲到這裡並把焦點移過去，卡片說明寫「N 項等你處理」。
- 列表每頁 10 列，用分頁切換，不會在方塊裡另外捲動。同一個專案、同一種類型的項目合併成一列，可展開看前 3 筆；同時選了專案與類型時不合併。只有整個篩選結果都在本頁時，合併列才寫出筆數。
- 待確認的決策可以直接按「確認」或「拒絕」；拒絕前會先請你確認。按「前往處理」會開啟對應頁面，並捲到、標出那一筆。
- 已列入 Agent 請求的決策標示「等待 Agent」。這是以專案為單位判斷：該專案有進行中、含決策的請求時，它的待確認決策都會標示。
- 只檢查了部分來源時，列表上方只留一行說明，並附上該來源所在頁面的連結。

### 工作歷程

- 依關鍵字、專案、完成日期與是否作廢篩選 Session；點一筆開啟 Session 面板。搜尋時，符合的字會在標題、專案名稱與摘要裡加粗標示；如果符合的是列上沒顯示的欄位，該列會標上「符合其他欄位」。每頁預設 20 筆，沒有符合的結果時不顯示「顯示 0–0，共 0 筆」。已套用的篩選顯示在清單上方，每個條件都能單獨移除，篩選時分頁標籤的數字顯示「符合數 / 總數」。選單按鈕也會直接顯示目前選的值。
- 「編輯 Session」的 Verification 可選通過、失敗、進行中或未執行。進行中表示驗證已開始但尚無確認結果；結束後更新同一筆記錄，並保留前後值與修改來源。歷史未回報保持獨立，不會因開始工作就視為通過。
- 「未結項」也在左側選單，數字是目前待處理的筆數（「工作歷程」旁的數字仍是 Session 總數）。可依專案、狀態及來源 Session 完成日期篩選。每筆是一列緊湊的內容：勾選框、內容（最長兩行，過長會截斷，滑過可看全文），以及專案、來源 Session、時間；右側的圖示按鈕可「標記完成」「標記不再需要」（篩選非「待處理」時顯示狀態，並可「重新開啟」）。標記立即生效、不再詢問，並以該列目前的狀態為準，若已被其他操作改變會略過並提示。畫面下方的提示約 8 秒內可按「復原」（滑過或聚焦提示時暫停倒數）；「重新開啟」只有在項目原本由你自己結案時才提供「復原」，由 Agent 或後續 Session 結案的項目重新開啟後無法復原，因為復原會把結案者改成你。勾選任一筆後才會出現批次列：「選取本頁」之後可再按「選取全部 N 筆」，涵蓋符合目前篩選的所有頁。套用時每 100 筆為一批；批次中已被改動的項目會略過，提示顯示「更新 N 項、略過 M 項」，中途失敗時顯示「已更新 N / M 項」，未套用的項目保持勾選。批次標記的提示同樣可「復原」。只有按過「選取全部 N 筆」之後，切頁才會保留選取；只選本頁時換頁會清空選取，切換專案、狀態或日期一律清空。同頁背景刷新保留仍待處理且仍在本頁的勾選。操作後焦點會移到下一列的第一個按鈕，沒有下一列時移到清單。手機寬度下清單隨頁面捲動（不在固定高度的框內捲動），操作按鈕在每筆下方靠右。「不再需要」的項目會標示是否由來源 Session 更新時移除，並可用「結案方式」隱藏這類項目，與你或後續 Session 判斷不需要的項目分開看。
- 同一個 Session 之後更新工作摘要時，若只是改寫某個仍待處理的未結項（文字相近），會保留原來的項目與建立時間，不會變成「不再需要」再多出一筆；內容明顯不同才視為取代。Agent 在 finalize 之後也能把它親自驗證完成的未結項結案（包含該 Session 自己留下、後來做完的項目），事件紀錄會顯示由哪個 Session（actor）完成，仍可在這裡看到並手動修正；證據不足或正在整理的項目不會被它更動。
- Session 面板可編輯主摘要、五段 workSummary 與 verification，連結其他 Session，作廢或還原；Evidence 可逐筆標示錯誤。手機寬度下，完成時間與耗時併成一行，開始與最後更新時間收在「開始與最後更新」裡；觸控裝置不顯示 `J`／`K` 鍵盤提示。
- Agent 新增的原生架構圖會顯示在面板的「圖表」區塊；點「展開閱讀」可放大、縮小、切換原始尺寸、適合畫面，並拖曳或用方向鍵移動畫布。按 `+`／`-` 縮放、`0` 適合畫面、`Esc` 返回工作記錄；重新載入網址仍會保留正在閱讀的圖表。歷史 Mermaid 以原始碼顯示，提供複製、下載與展開閱讀，也可以作廢及還原。
- 專案設定了 https 儲存庫網址時，commit SHA 會連到 commit 頁面。
- 在「系統狀態」頁最上方的「個人偏好」選了編輯器（VS Code 或 Cursor）之後，changed files 旁會出現「在編輯器開啟」連結。偏好只存在這個瀏覽器，連結只會指向記錄中專案資料夾內的檔案。

### 整理既有未結項

直接在 Agent 對話輸入：「請整理這個專案的未結項。」Agent 會為這個專案建立整理請求（沒有待處理項目時會告知；已有進行中的請求則沿用），也可以在工作歷程 → 未結項按「整理未結項」：不必先選專案，面板會列出有待處理項目的專案與各自的筆數（只有一個時直接顯示），選擇後即可建立請求；若清單原本已篩選某個專案，面板直接使用它，不會因為「選擇其他專案」而清掉你的篩選。Agent 只在你明確要求時才會發起，且不會自行更動項目狀態。Agent 會核對後續 Session，把有證據支持的項目直接結案為「已完成」或「不再需要」，每筆附一句理由與證據；本來就不是任務的項目（範圍排除、已知限制、未實測的平台、依你決定暫緩）會記錄為「已知限制」，不附證據。證據不足的項目保持未處理。結果不需要你先接受，可到工作歷程 → 未結項 → 整理未結項的「Agent 已結案」檢查：每筆一列，判定與理由在內容下方，右側圖示可開啟來源 Session、證據與「重新開啟」（立即生效，不提供「復原」）；勾選後才會出現批次「重新開啟所選」。

回到整理側面板可查看核對進度與「Agent 已結案 N 筆」；每筆列出判定（已完成、不再需要或已知限制）、理由，「來源 Session」與「證據」會開啟工作詳情。判斷不對時，可逐筆按「重新開啟」，或勾選本頁最多 100 項後按「重新開啟所選」，項目會回到待處理。Agent 提交時若有項目或證據已變更，整批不會寫入，請重新整理後再請 Agent 處理。請求與頁碼會保存於網址，長清單在固定區域捲動；All 仍每頁最多 100 筆。取消只停止尚未完成的請求，已結案的項目維持原狀。升級前留下、尚未審核的舊建議會被標為已拒絕，項目維持待處理。

整理進行中的快照項目，Agent 收尾或移除來源 Session 的 nextSteps 不會直接讓它們結案，只有整理請求本身的判定能改變它們。Web 人工逐筆／批次更新仍可使用。

### 工作知識

分成四個分頁，依處理順序排列；開啟「工作知識」時，只要有待確認決策就先顯示「待確認決策」，否則顯示「Knowledge」；左側選單的「工作知識」旁會顯示待確認決策與候選合計的筆數。切換分頁後，網址會記下目前的分頁：

- **待確認決策**：Agent 在工作中自行做的決定，每筆都連到來源 Session。「確認」是主要按鈕，會立即生效；「拒絕」會先請你確認，因為人工審查的結果無法復原；「整理成 Knowledge」在每筆的「更多」選單裡，開啟後內容已填好，標題請寫成別人搜尋得到的結論，標題與標籤不會預填。勾選決策後可用「確認所選」或「拒絕所選」一次處理多筆（拒絕同樣會先確認），一次最多顯示 200 筆。
- **候選**：Agent 提出的 Knowledge 候選，接受（可先修改）後才會成為 Knowledge。候選頁的「還有值得整理的 Session」會逐專案列出還沒整理、而且有已確認決策、驗證修復或被後續工作引用的 Session 筆數，每列有自己的「整理」按鈕，數字就是整理這個專案會清掉的筆數；沒有這類 Session 的專案不會列出。Agent 一次讀 10 筆，交回候選後會自動接著整理下一批，直到這個專案整理完；中途停下也沒關係，下次會從停下的地方繼續。不想繼續時，按該專案那一列或請求提示上的「停止」，這個請求會取消，Agent 之後送出也不會被接受。Agent 在專案累積至少 5 筆這類 Session 且超過 7 天沒整理時，可能在對話中提醒你一次，但不會在你沒要求時自行建立請求。提出時若與同專案的 Knowledge 或其他候選相似，卡片會列出相似紀錄、關係與相似度；這只是參考，不會阻止接受或拒絕。相似的 Knowledge 仍存在時可點標題開啟它。
- **Knowledge**：列出已接受的 Knowledge，每筆預設只顯示標題、類型、一行摘要與一行來源資訊，一屏可看到更多筆；按「展開詳情」才會顯示全文、標籤與適用路徑。顯示被 Session 確認與推翻的次數；變更紀錄面板列出來源 Session。
- **知識頁**：每個記錄中專案有「架構與慣例」「進行中的工作與未結項」「常見陷阱」三頁，也可以新增自訂問題。沒有篩選專案時，知識頁依專案分組，同名的頁面不會混在一起；點標題或「查看」開啟頁面，「自訂知識頁」不必先選專案，有多個專案時在視窗內選擇要建立在哪一個。面板內的內容依換行分成段落與清單，每段的來源收在「來源（N）」裡，預設列出前 3 筆，可展開全部。新 Session 先顯示「有新資料」，Agent 評估後可標記已檢查；只有內容結論需要改變時才建立新版本。引用來源在頁面儲存後被修改、作廢或還原時，頁面會獨立列出受影響段落、來源與原因供核對。每頁最多 12 段、內容合計 8,000 字；接近上限（11 段或 7,200 字）時，知識頁與編輯視窗會顯示目前用量，並建議先刪掉已不再適用的內容（已完成的項目、被後來推翻的事實）；仍放不下時，再把最大的幾段移到自訂頁面。仍然成立的內容不要刪減。不再需要的自訂知識頁可以在知識頁面板按「刪除知識頁」刪除：確認視窗會列出一併刪除的歷史版本數，刪除後無法復原，之後匯入較早的 JSON 匯出檔也不會把它加回。三個預設頁不能刪除。
  - 頁面由 Agent 依已記錄的 Session 改寫，每段都標示來源 Session，或寫「資料不足」。
  - 狀態篩選可查看有新資料、來源需要核對、最新、等待撰寫與已要求更新的頁面；也可以手動編輯或查看版本紀錄。

#### 請 Agent 處理待確認項目

待確認的決策、Knowledge 候選，以及需要重新確認的 Knowledge 不想一筆一筆看時，可以請 Agent 先處理：

1. 在「Knowledge」「候選」或「待確認決策」分頁上方的「Agent 審查請求」按「請 Agent 處理」。沒有選專案時，列出有待處理項目的專案與筆數，每列一個按鈕；只有一個專案時直接顯示；篩選選了專案時，按鈕寫明專案名稱與筆數。按鈕停用時，滑過會說明原因（例如已有開放的請求，或沒有可處理的項目）。
2. 請求建立後，方塊會顯示可複製的句子；回到你的 Agent，說「用 Work Intelligence 處理 Agent 審查請求」。沒有選專案時，方塊也會列出所有處理中的請求，每筆都能取消。每個專案同時只有一份開放的請求；請求會固定當下的待處理項目，一次最多 500 筆，超過的部分會顯示「N 筆超過上限未納入，完成後可再開一次請求」。
3. Agent 逐項核對來源 Session，直接確認、拒絕或接受項目，並寫下理由。證據不足的項目它會略過，留在你的待確認清單。請求上會顯示已處理、略過與仍待處理的筆數；處理中斷時會顯示原因。需要時可以取消請求，已處理的結果會保留。
4. 請求完成後，Agent 會接著更新受影響的知識頁。請求下方的「知識頁」列出涉及的頁面與狀態（已更新、已檢查、仍待更新、未變動），並顯示已更新或已檢查的頁數；按「開啟頁面」會在「知識頁」分頁打開該頁。狀態會隨頁面之後的更新而變化，列出的頁面則是請求完成當下決定的。

Agent 的處理立即生效，不必再經過你確認。要檢查結果，在「候選」與「待確認決策」分頁右上角把篩選從「待確認」切到「由 Agent 處理」：每筆會列出處理結果、理由與處理時間。覺得不對時按「推翻」，項目會回到你的待確認清單；Agent 因此建立的 Knowledge 若仍在使用中，會一併封存。

需要重新確認的 Knowledge 指可能過時（後續工作改了它涵蓋的檔案）或被後續工作指出矛盾的 Knowledge，和注意事項裡的判斷相同。Agent 會讀目前的程式碼或之後的工作記錄，選擇「仍成立」「封存」或「改寫後取代」（寫一筆新的 Knowledge 取代舊的），並附理由；證據不足時保持待處理，也不會只因為相關檔案改過就封存。結果列在「Knowledge」分頁清單上方的「由 Agent 處理的 Knowledge」。按「推翻」時，「仍成立」會撤回確認，「封存」會恢復為使用中，「改寫後取代」會封存新的這筆、恢復原本的 Knowledge。

### 工作圖譜

- **關係圖**：Project、Session、Knowledge、Evidence、檔案與 Session 關聯。第一次開啟時只顯示最近有 Session 的記錄中專案，網址帶有 `project` 時以網址為準；專案選單可改選其他專案或「全部專案」。節點上限、畫面預覽量與「推導的關係」收在「顯示設定」裡。
  - 實線是記錄下來的關係。可以開啟「推導的關係」，以虛線顯示常被一起修改的檔案。
  - 在節點面板選另一個節點，會逐段說明兩者如何關聯。
- **時間軸**：每個專案一條泳道。
  - 拉遠時每天一根長條，依驗證結果分色；點一下放大到那天。
  - 拉近後，Session 畫成長條或點，關聯畫成弧線，Knowledge 事件畫成標記。
  - 可以放大、縮小、顯示整個期間，或切換成依日期分組的清單；手機寬度自動使用清單。
- **熱點**：被最多 Session 修改的檔案或目錄，附驗證失敗與未執行的比例，以及最近的 Session。工作報告的「風險」也會列出本期熱點。

### 用量

「用量」頁整理本機 Claude Code 與 Codex 的紀錄，回答「Agent 這段時間做了多少事、Token 花在哪裡、Work Intelligence 的哪些操作被呼叫最多」。從桌面 App 開啟的 Dashboard 和用 `pnpm bootstrap` 安裝的 Dashboard 都有這一頁，位置在左側選單「系統狀態」旁。

- **選專案**：列出「記錄中」的專案，預設是目前的專案，可以多選或選「全部專案」。每個專案旁邊顯示偵測到幾個 Claude Code 資料夾和幾個 Codex 紀錄檔。
  - Claude Code 的資料夾依專案位置自動對應，worktree 的資料夾會一起算進同一個專案。
  - Codex 依每份紀錄開頭記下的工作目錄判斷，工作目錄在專案底下才算。工作目錄只用來比對，不會顯示或輸出。
  - 偵測不到時，頁面會說明原因：找不到 Claude Code 或 Codex 的資料夾、沒有讀取權限，或資料夾裡沒有屬於這個專案的紀錄。
  - **Monorepo 與共用資料夾**：如果把同一個 monorepo 的幾個子資料夾（例如 `assistant`、`devtools`、`devdocs`）分別登記成專案，卻常在上層資料夾開啟 Claude Code 或 Codex，那些對話原本不屬於任何一個專案。現在這幾個專案會在選專案區合成一組，組標題旁有「共用資料夾」標籤和「選取整組」按鈕，一次選好整組。
  - 共用資料夾裡的每個對話只計一次，並依序用三種依據分給其中一個專案，頁面會顯示每個專案各有幾個對話是用哪一種依據分到的：
    1. **projectRoot**：對話裡 Work Intelligence 呼叫指定的專案位置。呼叫指到不同專案時，取次數最多的那個；次數相同就看下一項。
    2. **檔案路徑**：Claude Code 讀取、編輯或寫入的檔案。落在某個專案底下的次數要超過組內所有命中的一半，而且至少 3 次。Codex 的紀錄沒有這項。
    3. **cwd**：對話各行記下的工作目錄（Codex 是每個 session 與每回合開頭記下的）。判斷方式和檔案路徑相同：超過一半且至少 3 次。工作目錄中途換資料夾時，以出現行數最多的專案為準。
  - 三項都判斷不出來的對話，歸入「<組內專案名稱>共用（未分配）」。只選組內部分專案時，只計入分到這些專案的對話，其他專案的對話和未分配的對話都不計；選取整組時，未分配的對話才會一起計入。這些專案名稱、對話數與 Token 會顯示在結果的「共用資料夾的對話」，路徑與資料夾名稱不會顯示，只用來比對。
- **進階：手動加入資料夾**：專案搬過位置、對應不到時，可以填入資料夾的完整路徑，最多 20 個。這些路徑只留在這一頁，不會出現在結果或複製的文字裡。
- **期間**：近 7 天、近 30 天或自訂。按「掃描用量」開始；第一次開啟時會自動掃描一次。
- **頁面內容**：
  - 上方摘要：主要數字是「輸入 + 輸出（不含快取）」，也就是未快取的輸入加上輸出。旁邊是回合數、工具呼叫數、Work Intelligence 占工具呼叫的比例，以及快取讀取、快取寫入。快取讀取與快取寫入另外列出，不加進主要數字：快取讀取的量常是輸入加輸出的幾十倍，加進去會讓數字看起來很大，卻說不出 Agent 實際多做了多少事。
  - 快取讀取占比：快取讀取 ÷（未快取輸入 + 快取讀取 + 快取寫入），也就是輸入端的 Token 有多少比例是從快取讀出。紀錄裡沒有每次請求的命中與否，所以這不是命中率。
  - Token 組成：分成兩列，各用自己的比例尺。上面一列是計入主要數字的輸入與輸出，下面一列是不計入的快取讀取與快取寫入，中間寫出快取讀取是主要數字的幾倍。輸出包含紀錄中有回報的推理（reasoning）Token。
  - 每日趨勢：每天的輸入與輸出疊成一根長條，日期依這台電腦的時區。
  - 目前 5 小時區段：只在期間包含現在、而且最近 5 小時內有用量時顯示，每個 Agent 一張。區段從第一筆用量所在的整點開始，長度 5 小時；距上一筆用量滿 5 小時或到了區段終點，就從下一筆用量重新開始。顯示區段內的輸入 + 輸出、已經過的時間、距區段結束的時間，以及每分鐘的輸入 + 輸出。這只是依紀錄推算的時間區段，不代表方案額度。
  - 模型分布：依 Agent 與模型列出輸入 + 輸出和快取讀取。模型名稱來自紀錄（Claude Code 是每則回覆記下的模型，Codex 是每回合開頭記下的模型）。看起來像檔案路徑、或像 `<synthetic>` 這類佔位值的名稱，一律顯示為「未標示模型」。
  - Work Intelligence 操作：依操作名稱（例如 `work_get_context`）列出呼叫次數、回應字元的總和與平均。
  - 用量最多的對話：依輸入 + 輸出排序。每個對話只用 `session-1` 這類序號表示，附回合數、工具數與 Token。
  - 其他工具的前幾名。
  - 每張圖下方都有同樣數字的表格。
  - 頁面不換算金額，也沒有價格表；掃描不會連到網路。
- **複製給 Agent**：先顯示要複製的文字，確認後再複製到剪貼簿。文字只有加總數字、專案名稱、模型名稱、操作名稱、對話序號，以及共用資料夾的未分配對話數與各專案依哪種依據分到幾個對話，沒有路徑、資料夾名稱或訊息內容。
- **讀取方式**：只讀取紀錄檔，不寫入 `~/.claude` 或 `~/.codex`。解析在背景進行，一次最多 60 秒，換條件重新掃描時會取消前一次。沒有變動的檔案會沿用上次的結果，只有新增的部分才重新讀取。

> **給開發者與命令列使用者**：同樣的報告可以在 checkout 目錄用命令產生，預設是目前目錄所在的專案，沒有對應時改用全部「記錄中」的專案。

```bash
pnpm usage:report
pnpm usage:report -- --project my-project --since 2026-11-01
pnpm usage:report -- --all --json
pnpm usage:report -- --for-agent
```

`--for-agent` 輸出的文字和「複製給 Agent」相同。`--json` 的欄位和頁面相同；1.6.66 的 `costShares`、`costMultipliers` 與對話的 `estimatedCostUnits` 已移除，改為 `tokens.primary`、`tokens.cacheReadShare`、`models`、`daily`、`blocks` 與對話的 `primary`。舊的 `node scripts/agent-usage-report.mjs <檔案或資料夾>` 仍可使用，輸出只多一行 Work Intelligence 操作統計。

### 請 Agent 查詢時

- 可以限定期間，例如「上週」「六月」。Agent 會以日期範圍查詢，只回傳那段時間的記錄。
- 開工時提供要改的檔案路徑，若這些檔案最近 30 天常被修改，Agent 會收到熱點提醒。

## 外觀、語言與操作提示

- **淺色／深色主題**：按頁首右側的太陽或月亮按鈕切換。淺色主題使用柔和的灰色底，不是純白，長時間使用較不刺眼。「系統狀態 → 個人偏好 → 外觀主題」（位於頁面最上方）有三個選項：跟隨系統、淺色、深色。選「跟隨系統」時，作業系統切換淺色／深色模式，介面會跟著變。
- **介面語言**：頁首的語言選單（「文A」圖示）可切換「繁體中文」與「English」，也可以在「個人偏好 → 介面語言」設定。第一次開啟時依瀏覽器語言決定。只有介面文字會翻譯；Session 摘要、報告、Knowledge 與 Agent 寫入的內容維持原本記錄的語言。
- **指令面板**：`Ctrl`/`⌘` + `K` 除了搜尋 Session、Knowledge 與跳頁，也能輸入「主題」「theme」或「語言」「language」直接切換。
- **載入提示**：換頁或按重新整理時，畫面最上方會出現細長的進度條；很快完成時不會顯示。
- **鍵盤操作**：按 `Tab` 進入頁面時，第一個焦點是「跳至主要內容」，按 `Enter` 可略過頁首與側欄。
- **減少動態效果**：作業系統開啟「減少動態效果」時，所有轉場與動畫都會關閉。

主題與語言設定只存在目前的瀏覽器（localStorage），不會寫入資料庫，也不會影響其他瀏覽器或電腦。

## 備份、匯出與匯入

- API 啟動時會檢查每日自動備份，之後每小時檢查一次；依 server 本機日曆日每天最多一份，預設保留最近 3 份。資料庫有待套用 migration 時，程式會先額外建立標有目標 schema 版本的備份。
- 手動備份可在「專案 → 資料備份」選「立即備份」，或執行 `pnpm db:backup`。
- 「專案 → 資料備份」會列出備份種類、時間、大小與總大小；刪除前會顯示檔名與種類並要求確認，刪除唯一一份列出的備份時會額外警告。CLI 可用 `pnpm db:backups` 列出，或在互動終端執行 `pnpm db:backups --delete <檔名>` 確認刪除。
- 「專案 → 資料備份」頁首說明兩種搬移方式：換電腦或合併兩台電腦的記錄，用「匯出專案資料」與「匯入專案資料」（JSON）；整台電腦損壞、要整份還原，用「匯出整份資料」（.sqlite）。匯出與匯入各自一個區塊。
- 整份 .sqlite 的還原，桌面 App 在「資料」分頁選「從備份還原」，也可以選其他位置的備份檔，不需要輸入指令。**給開發者與 CLI 使用者**：沒有桌面 App 的 Web 頁會多一個「進階：用指令還原」，裡面是 `pnpm db:restore` 的步驟。
- 匯入區塊用「選擇檔案」按鈕選檔，也可以把 .json 檔拖放到該區塊（一次一個檔案）；不是 .json 或超過 256 MiB 的檔案會被拒絕，目前已選的檔案與預覽不受影響。選好檔案後，頁面會捲到「匯入預覽」並把焦點移到預覽上。預覽的五個數字各有一行說明：新增是這台電腦沒有的紀錄，將更新是匯入的較新、會更新本機，保留本機是保留本機版本，略過是本機已有相同資料，衝突是目前設定下不會寫入、維持本機。「各類型明細」列出每種紀錄各自的數字。
- 預覽沒有任何會寫入的變更時（由 server 判斷），不會出現「確認並匯入」。若所有差異都是衝突，畫面說明目前設定下沒有可匯入的變更：用「只新增」且檔案較新時可按「改用較新者優先」，只有路徑不同時請為找不到的資料夾選新位置，也可以「放棄這個檔案」；若檔案本來就沒有需要寫入的資料，按「完成」清除檔案。匯入完成後，結果會留在區塊內，並提供「前往專案清單」；離開這個分頁後結果會清除。
- 專案刪除後，刪除前備份和其他較早的備份仍可能包含該專案資料；可從「專案 → 資料備份」檢視並刪除不再需要的備份。
- 資料庫維護會在執行 `VACUUM` 與重建搜尋索引前建立並驗證一份備份。請先停止 `pnpm start`，並關閉會啟動 MCP 的 Codex／Claude 對話，再執行 `pnpm db:maintain`。命令會先檢查資料庫完整性及獨佔鎖，之後整理 SQLite、更新統計資訊、重建搜尋索引；若無法取得鎖或備份失敗，會停止維護；被占用時會列出 server 與 MCP 連線狀態。完成或未完成的結果可由 `pnpm check` 唯讀查看。`pnpm check`（`pnpm bootstrap` 最後也會執行）也會讀取資料庫檔內的未使用空間：至少 1 MiB，且達 5 MiB 或檔案的 20% 時，提示「可回收空間」並建議停止服務後執行 `pnpm db:maintain`；它不會自動執行維護。
- 寫入 Session、Evidence、Knowledge 等文字前，會遮蔽已知格式的憑證，並移除 `<private>…</private>` 包住的內容（換成 `[REDACTED:private_block]`；區塊必須有結尾標籤，沒有結尾的 `<private>` 會照原文保存）。不希望被保存的內容，可請 Agent 用這組標籤包住。
- `pnpm db:redact` 只讀掃描並顯示各類型遮蔽數量與受影響 Session 數；確認後先停止 server、關閉 MCP Agent，再用 `pnpm db:redact --apply` 遮蔽目前資料庫。命令會先建立一份包含原始內容的備份。既有備份與先前匯出檔不會被改寫；請在「專案 → 資料備份」檢視並處理不再需要的檔案，必要時重新匯出可攜式 JSON。
- 完整 SQLite 快照可在 Web 介面匯出，或使用 `pnpm db:export <檔案.sqlite>`。快照包含所有專案與工作記錄。
- 可攜式 JSON 支援單一或全部專案：`pnpm db:export --project <專案名稱或 id>`、`pnpm db:export --all`；`--out <檔案.json>` 指定輸出位置，只寫 `--out` 時等同 `--all`（不會產生 SQLite 快照）。在 Web 匯入或執行 `pnpm db:import <檔案.json> --dry-run`，先查看新增、更新、保留本機、略過、衝突及路徑轉換，再確認匯入；新專案會以暫停狀態加入。相同專案 ID 已存在時自動沿用本機根路徑。兩台電腦都在記錄同一專案時用「較新者優先」（`--strategy newer-wins`）：兩邊都改過的資料取較新者、本機較新的保留、歷史只新增、撞號的知識頁版本依時間重新編號後並存；「只新增」（預設 `merge`）不覆寫既有資料。可匯入 schema 31 起的匯出檔（v1.6.7 以後匯出）；較新版程式匯出的檔案要先更新本程式才能匯入。
- 匯入前會檢查檔案格式。Knowledge 與 Knowledge 候選的 `appliesTo` 必須是最多 100 筆、每筆最多 4,096 字元的文字清單；這比平常寫入的限制（30 筆、1,000 字元）寬，因為遮蔽憑證後的文字可能變長，所以 Work Intelligence 產生的匯出檔都能匯入。超過寫入限制的項目照原樣保存與顯示，但不用來比對檔案。超過 100 筆或 4,096 字元時，預覽與匯入都會顯示「匯入檔格式錯誤：knowledge.applies_to_json 必須是最多 100 筆、每筆最多 4,096 字元的文字清單。」（候選為 `knowledge_candidates.applies_to_json`），不寫入任何資料；這表示檔案被修改過或不是由 Work Intelligence 產生。
- 確認匯入後（Web、REST 與 `pnpm db:import` 都一樣），程式先建立並檢查一份匯入前備份（`pre-import-…`，在「資料備份」列為「專案資料匯入前」），再寫入資料；檔案中的資料這裡都已經有了時，不會寫入任何東西，也不建立備份，畫面會說明資料沒有變更；備份寫不出來時不會匯入，顯示「無法建立並檢查安全備份，資料沒有變更」。要撤銷一次匯入，停止服務後用 `pnpm db:restore` 還原這份備份；還原會一併捨棄這份備份建立之後到還原之間寫入的所有其他資料（例如之後保存的 Session）。匯入前備份獨立保留，份數與自動備份相同（預設 3 份），不會擠掉手動備份。預覽不寫入任何東西。
- 匯入檔中如果有列所屬的專案或 Session 不在檔案裡（例如檔案被手動刪減過），這些列無法匯入；預覽與結果會把它們算在「衝突」，原因顯示「所屬專案不在匯入檔中」等，類別為「匯入檔缺少上層資料」，不會默默消失。其他列照常匯入。
- 匯入在背景執行，進行中其他頁面與 Agent 仍可正常讀寫。
- JSON 匯出未加密。SQLite 快照與備份也應視同包含私人工作記錄，請存放在可信任位置。

## 換電腦與還原

一般使用者請用下方「在桌面 App 內還原、整理與更換備份位置」的步驟。

> **給開發者與命令列使用者**：搬移整份資料前，先停止 Work Intelligence server，並關閉會啟動 MCP 的 Codex／Claude 對話，再從備份或舊電腦匯出完整 SQLite 檔案。在新電腦執行：

```sh
pnpm build
pnpm db:restore <匯出檔.sqlite> --remap-root <舊專案上層路徑>=<新專案路徑>
pnpm start
```

若專案路徑沒有改變，省略 `--remap-root`。可以重複指定多組路徑轉換。還原會檢查 SQLite 完整性與 schema 版本，並在取代目前資料前先備份目前資料庫；若偵測到資料庫仍被 server 或 Agent 開啟，會停止還原。完整選項見[REST API 文件](rest-api.md)與 README 的「備份與換電腦」。

### 在桌面 App 內還原、整理與更換備份位置

桌面 App 的視窗不需要任何指令就能做這些事（都在「資料」與「設定」分頁）：

- **從備份還原，換新電腦時對應專案路徑。** 「資料」分頁的「從備份還原」列出備份資料夾裡的備份，也可以用「選擇備份檔…」選別處的檔案。若備份記錄的專案資料夾在這台電腦上不存在，App 會問你它們現在在哪裡：選一個資料夾，App 會找出同名的專案資料夾並自動對應路徑，可以重複選擇，也可以略過、保留舊路徑。確認後 App 會先自動備份目前的資料，再停止服務、取代資料庫並重新啟動；失敗時原本的資料庫不會被更動。
- **整理資料庫。** 「資料」分頁的「整理資料庫…」會先自動備份，再檢查完整性、壓縮資料庫檔案並重建搜尋索引。「檢查完整性」只讀取資料，不會更動任何東西。有 Agent 開著、匯入或備份進行中時不會開始。整理前的備份留在備份資料夾；「狀態」分頁與 Web「系統狀態」頁都會顯示可回收的空間和最近一次整理的結果。
- **更換備份位置。** 「設定」分頁的「更換備份位置…」可以改用別的資料夾：App 會確認資料夾可以寫入，網路磁碟不能用，外接磁碟或雲端同步資料夾會先問你。更換位置只影響之後的備份，已經存在的備份不會被移動，仍留在原來的資料夾。
- **連接埠被占用時。** 如果你設定的連接埠無法使用，App 會改用上次正常運作的連接埠，並在「狀態」分頁說明；你的設定不會被改掉，資料庫也不會被自動換成別的檔案。上次的連接埠也失敗時，App 停在狀態分頁等你處理，資料不會被更動。

### 語言、登入時自動啟動、Agent 狀態與診斷

- **語言**：「設定」分頁最上方的「語言」卡片，用「顯示語言」選一個：「跟隨系統（繁體中文）」（預設，括號內是目前系統讀到的語言；系統語言以 zh 開頭就是繁體中文，其他都是 English）、「繁體中文」或「English」。App 視窗、工作列選單、macOS 應用程式選單與 App 的對話框會立刻切換，不需要重新啟動。App 管理的 Dashboard 使用同一個語言：在 Dashboard 改語言時，App 的設定也會跟著改；唯一的例外是 App 選「跟隨系統」時，在 Dashboard 選了系統本來就讀到的語言，App 仍維持「跟隨系統」。獨立執行的 server（不是由桌面 App 啟動）仍把 Dashboard 的語言記在瀏覽器。
- **登入時自動啟動**：「設定」分頁的開關可以隨時打開或關閉（Windows 與 macOS）。開關只送出開或關；開啟仍以你自己按下開關作為同意。卡片顯示系統實際的狀態：若系統的啟動項目在系統設定中被關掉，或 macOS 還在等待核准，卡片會說明原因，並提供開啟系統設定的按鈕。
- **Agent 分頁**：為 Codex 與 Claude Code 各顯示一張卡片，狀態包括「已連線」、「已設定，待確認」、「需要重新連線」與「設定衝突」。每種狀態的處理方式見 [Agent 設定](agent-setup.md#卡片狀態)。
- **診斷分頁**：先顯示預覽，再按「匯出診斷資訊…」存成 JSON 檔。檔案會遮蔽個人路徑、授權碼、權杖與電子郵件，不含工作記錄內容；App 不會上傳它。回報問題時附上即可。

## 更新 Work Intelligence

取得新版原始碼或 Release source archive 後，先停止 Work Intelligence server 與 MCP 用戶端，再於新版專案目錄執行：

```sh
pnpm install --frozen-lockfile
pnpm build
pnpm check
pnpm start
```

保留原本的 `WORK_INTELLIGENCE_DB` 設定與資料庫檔案位置。首次由新版程式開啟舊 schema 的資料庫時，系統會先建立 migration 前備份，再自動套用必要的 migration；備份失敗時會停止升級。不要手動刪除 migration 記錄或直接編輯 SQLite。若已安裝登入自動啟動服務，更新程式目錄前先執行 `pnpm service:uninstall`，更新並確認正常後再依[服務指南](service.md)重新安裝。

MCP 只更新實作時，系統狀態顯示「有新版可用」，原連線仍可繼續讀寫。schema／Agent 契約變更或相容性無法判定時，才需要重新啟動或重新連線 Codex／Claude。MCP 卡片分開顯示「需要重新連線」與「有新版可用」的程序數。版本與 schema 可由 `/api/health` 查看，UI 側欄也會顯示程式版本。版本規則、tag 發行及完整升級前檢查見[發行指南](release.md)；變更摘要見 [CHANGELOG](../CHANGELOG.md)。


### 閱讀結構化架構圖

Agent 更新後，可附加[架構圖 v1](architecture-diagram-format.md) 快照。展開 Session 的架構圖後，左側群組或上方選單切換範圍；選取節點查看完整說明、來源位置與直接關係，「查看直接關係」聚焦該節點及相鄰節點。節點資訊可收合以增加畫布空間。手機或縮窄的閱讀面板上，群組改用上方選單，節點資訊移到畫布下方；切換依面板寬度判定。

## 桌面 App 檢查更新

桌面 App 的「更新」卡片在視窗的「設定」分頁。也可以從工作列圖示選「檢查更新…」，它會開啟「設定」分頁並開始檢查。

App 不會自動檢查更新：沒有背景查詢，也沒有開關。只有按下「檢查更新」時才會連線到 GitHub。

按下後會顯示以下其中一種結果，每種結果都提供「開啟發行頁面」：

- **已是最新版本**：目前版本已是最新。
- **有新版本**：顯示新版本號、發佈日期與更新內容（純文字）。可按「下載 Windows 安裝檔」或「下載 macOS 安裝檔」，由預設瀏覽器下載該平台的安裝檔。Windows arm64、Linux 等其他平台只提供發行頁面。
- **無法連線**：目前無法連線到 GitHub，請確認網路後再試。
- **查詢次數受限**：GitHub 暫時限制查詢，會顯示可再試的時間。App 不會自動重試。
- **無法取得**：顯示錯誤代碼，請稍後再試。

App 不會替你安裝更新。下載後請驗證檔案：

1. 在同一個發行頁面下載 `SHA256SUMS.txt`。
2. 計算安裝檔的 SHA256 並與檔案中同名的值比對。Windows（PowerShell）可執行 `Get-FileHash -Algorithm SHA256 .\Work-Intelligence-<x.y.z>-win-x64-setup.exe`；macOS 可執行 `shasum -a 256 Work-Intelligence-<x.y.z>-mac-arm64.dmg`（Intel 為 `-mac-x64.dmg`）。
3. 若兩者不同，請刪除該檔案並重新下載。

安裝檔未經簽署（macOS 為 ad-hoc 簽署，Windows 未簽署），因此安裝時可能出現提示：

- **macOS**：Gatekeeper 可能阻擋開啟。請到「系統設定 → 隱私權與安全性」，在下方找到該 App 的提示後選擇允許開啟。
- **Windows**：SmartScreen 可能顯示「Windows 已保護你的電腦」。選擇「其他資訊」，再選擇「仍要執行」。

這些提示不代表檔案有問題；請先完成上述 `SHA256SUMS.txt` 核對。手動安裝新版時，你的資料會保留。

**隱私**：只有按下「檢查更新」時才會送出請求。請求只向 GitHub 查詢公開的發行版本列表，不含 App 版本、作業系統、機器識別碼、帳號、權杖或 cookie。啟動時與閒置時都不會送出。
